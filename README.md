# 网申自动填写（nw-autofill）

Chrome / Edge MV3 扩展。在公司自建网申页面上，按你维护的一份标准简历把客观字段一次填好，
填不出的明确标出来交给你决定。**不替你提交、不解验证码、不做测评、不上传附件。**

当前进度：P0 + P1 的 Markdown/AI 辅助导入、P2 的中文框架家族（Element UI / AntD / Moka）、
P3 的 SF / Workday 适配与 AI 兜底都已落地，另有中英两份值与 217 条离线回归 + 191/191 判分。
**但这套扩展还没在真实浏览器里跑通过** —— 所有站点结论来自 `test-forms/` 仿真 + 你导出的页面结构，
第一次实测请以"预览 → 逐条核对 → 再写入"的方式用。

## 装载试用

1. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选择本仓库根目录（能看到 `manifest.json` 的那一层）
4. 打开某个网申页面 → 点工具栏图标 → 侧边栏「导入简历 Markdown」粘贴简历全文 → 解析并填入
   （不想用导入的，可以「下载空白模板」拿到全部 526 个可填项，手填后在 JSON 区保存）
5. 回到网申页面点「扫描并填写」；不满意可点「回滚本次填写」

**改完代码怎么确认重载真的生效了**：侧边栏顶栏那行会报 `构建 <日期>-<序号>`（唯一来源是 `core/build.js`）。
如果它显示"后台没跟上：…"，说明面板是新的、MV3 的 service worker 还是旧的那一份
（旧 worker 挂着连接时不会立刻退场，这是本扩展最常见的"我明明重载了"成因）。
修法：在 `chrome://extensions` 把本扩展的开关**关掉再打开**，然后关掉侧边栏重开。
只有探针导出物里的 `probeBuild` 与你看到的构建号一致，那份 JSON 才对得上当前代码。

## 颜色含义

- 绿：高置信，已填入，仍需你扫一眼
- 黄：填了但置信度不足或属敏感字段，**请复核**
- 红：尝试写入但页面回读不一致（受控组件没吃进去）
- 灰：交给你手动处理（主观题、附件、验证码、无对应资料）

## 映射表先行：写入前的那一道确认（默认开着）

侧边栏「本页映射表」把这一页**每一栏**摊成一行：页面这一栏（标签 / 来源 / 板块 / 选项 / 说明）、
我们的判定（判给哪个资料槽位，或为什么没定）、凭什么（来历 + 证据 + 置信 + 说明）、
现在是谁写的（我们上一轮写的 / 站点或你自己填的 / 空的）、改判（下拉 + 一句理由）。

开着「映射表先行」时：

- 顶部那枚按钮变成**「扫描并出映射表」**，点它不会动页面一个字节；
- 真正落笔只认**「按此映射填写」**那一个钮；
- 表顶那句话会说清这一轮做了什么：`映射表先行：这一轮只出了这张表，页面一个字节都没改。`

改判只做一件事：决定**这一格是什么**。取值仍来自你的资料 —— 资料里那一栏空着，
表里就照旧说"钉住了槽位但资料是空的"，不会拿别的栏位顶替。下拉里只列资料中真实存在的槽位
（先输关键词筛，默认给前 40 个）；自造路径在后台就被拒，并当场念出理由。
「这一栏不自动填」是另一种决定：这一栏进「需要你处理」，原因写 `这一栏你在映射表里勾了「不自动填」`。

改判能记住：**勾「改判同时记住到本站」**才会落盘（`chrome.storage.local.nwSiteRules`，
按站点分桶、只在这一站生效、里面只有"栏位长什么样 → 槽位名"，没有你的取值）。
不勾就是本轮生效，关页就没 —— 面板不会替你偷偷记。规则按**栏位指纹**认栏，
所以 SPA 重建 DOM、换一步表单都还能命中；代价是同页两栏自述完全相同时共用一条规则，
这种情况表里会标 `这一页有 N 栏自述完全相同`，并且那一栏强制黄字。

表上方的「计划校验」是落笔前的整页算术，每条都带下一步：资料有 3 段而页面只排了 1 组、
页面有 3 组而资料只填了 1 段、同一个只能填一次的槽位被两栏认领、必填栏没安排值、
整页一栏都不写（附本轮原因分布）。「导出映射表（无取值）」给的是脱敏视图：
只有页面文字、槽位名与依据，屏幕上那份的回读值不进文件。

关掉的办法：取消勾选「映射表先行」。那一格关着时按钮回到「扫描并填写」（直接写），
映射表照旧出，只是不再拦着写入。

## 认选项：下拉里该选哪一项（默认不发出你的任何取值）

有些栏位我们把"它是哪一栏"判对了，却对不上页面给的那一项：页面问「是否全日制」而资料里存的是「全日制」；
港页写 `Right of Abode Holder` / `Holder of IANG`，而资料里写「永久居民」「IANG（内地应届毕业生留港计划）」。
这类栏位在映射表里标着「需要选一项」，点**认选项（下拉里该选哪一项）**问一次。

两条通路，默认走第一条：

 · **只发页面的话**：把这一栏的选项文字发给模型，让它给每一项归一个**封闭代号**
   （`IANG` / `HK_PERMANENT_RESIDENT` / `FULL_TIME`…）；你资料里那条值在**本机**折成同一个代号，
   两边相同才落这一项。折不出代号、或有两项都说得通 → 不猜，继续留在「需要你处理」。
 · **允许 AI 看取值**（勾选框，默认关）：把"我打算写进这一栏的那条值"一起发出去，模型直接挑那一项。
   勾了就能用，不必逐次确认；每次回答都会告诉你"这次发了哪几栏的取值"（只报栏名，不报值）。
   **永不出门**：证件号、护照号、电话（含区号分机）、姓名与单独的姓/名（本人、家属、紧急联系人、推荐人、内推人）、
   微信号、经历正文与声明勾选。被拦下的栏位会逐条列出原因，不会静默跳过。

两种模式都只许模型**指认页面已有的那一项**：写进控件的是页面自己的选项文案与码值，
模型给的任何文字都不进值。工作许可 / 签证类别这类是一句合规声明，即使不算敏感也保持黄字核对。

顺带一条口径修正：港站的「Work Permit」通常不是 Yes/No，而是**在港签证/进入许可类别**的下拉
（TTPS / GEP / ASMTP / IANG / QMAS / 受养人 / 学生 / 永居…，见入境处那一页）。
资料里那一栏现在是枚举，词表按 [IMMD Visas / Entry Permits](https://www.immd.gov.hk/eng/forms/hk-visas.html) 收。
判据与取舍记录在 [docs/AI-VALUE-ALIGNMENT.md](docs/AI-VALUE-ALIGNMENT.md)。
