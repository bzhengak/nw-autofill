# 网申自动填写（nw-autofill）

Chrome / Edge MV3 扩展。在公司自建网申页面上，按你维护的一份标准简历把客观字段一次填好，
填不出的明确标出来交给你决定。**不替你提交、不解验证码、不做测评、不上传附件。**

当前进度：P0 + P1 的 Markdown/AI 辅助导入、P2 的中文框架家族（Element UI / AntD / Moka）、
P3 的 SF / Workday 适配与 AI 兜底都已落地，另有中英两份值与 217 条离线回归 + 191/191 判分。
**但这套扩展还没在真实浏览器里跑通过** —— 所有站点结论来自 `test-forms/` 仿真 + 你导出的页面结构，
第一次实测请以"预览 → 逐条核对 → 再写入"的方式用。

## 装载试用

1. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选择本仓库根目录（能看到 `manifest.json` 的那一层）
4. 打开某个网申页面 → 点工具栏图标 → 侧边栏「导入简历 Markdown」粘贴简历全文 → 解析并填入
   （不想用导入的，可以「下载空白模板」拿到全部 526 个可填项，手填后在 JSON 区保存）
5. 回到网申页面点「扫描并填写」；不满意可点「回滚本次填写」

> P0 阶段简历数据要靠手工维护 JSON。Markdown / PDF 自动解析在 P1。

## 颜色含义

- 绿：高置信，已填入，仍需你扫一眼
- 黄：填了但置信度不足或属敏感字段，**请复核**
- 红：尝试写入但页面回读不一致（受控组件没吃进去）
- 灰：交给你手动处理（主观题、附件、验证码、无对应资料）

## 中英两份值（英文网申用得上）

「分类编辑」顶部有「中文 / English」两枚按钮，**只翻这个编辑区**：同一栏位在英文模式下显示英文名、
写英文值，切回中文又是原来的样子；这个选择会记住（`settings.editorLang`），重开面板不会把你补到一半弹回中文。

两份值存在同一份简历里的两个桶：中文在 `education.0.school`，英文在 `en.education.0.school`
（`profile.en` 是一棵同结构子树）。**保存只写当前语言的桶** —— 补英文不会把中文值盖掉，
清掉英文也不会连带清空中文。

不是每栏都要抄两遍，下面这些**两种语言共用一份**，英文模式下直接显示、直接写：

- 语言中性的控件类型：日期、数字、邮箱、电话、链接、文件等；
- 值里本来就没有汉字的：拼音姓名 `Zhang` / `Wei`、`GPA 3.8`、`2021-09`；
- 站点自己会翻译的枚举：英文模式下选项显示 `Male`，**存进简历的仍是规范值 `男`**
  （把 `Male` 写回去会让选项匹配、体检、回读三处一起错乱）。

真正需要补的是"中文有值、英文没值"的那几栏：编辑区会给它们一条橙色标记，顶部的计数告诉你还缺几栏
（灰色占位符就是那一栏的中文写法，照着翻即可）。

填写时读哪一份由**页面**决定，不由编辑区的开关决定：`core/matcher.js` 先看这一页标签是中文还是英文
（`detectPageLanguage`），英文页取 `en.` 值；标签里明写"中文"的栏位（港企常见的「姓名(中文)」）仍然取中文值。

**缺英文值时默认不写**，那一栏进「待你处理」，面板会说明"这一页是英文表单，N 个槽位只有中文写法，
已故意留空"——把「南京大学」写进 `School Name` 属于典型的"看起来填好了、其实全错"。
赶时间可以在「分类编辑」底部勾上「英文表单遇到只有中文写法的栏位：写中文并标黄」
（`settings.enMissingMode = 'zh_yellow'`）降级：会写中文，但一律黄字并写明"写的是中文值"。

## 点开自定义下拉（需要你显式授权）

Element UI / AntD / `role=combobox` 这类下拉没有 `<select>`，选项是点击后渲染到 body 末端的弹层，
打字不会选中任何值。侧边栏「允许点开自定义下拉并选中」勾上后才会真的点击页面控件；**默认关**。

边界（`dom/select-opener.js` + `dom/safety.js`）：

- 「什么算选择控件触发器」在 `SELECT_TRIGGER_SELECTOR` 里定义一次，扫描、点击闸门、opener 共用；
  闸门仍然生效：提交、导航、附件、其它按钮一律不点（判分表单里 `mustNotTouch` 盯着 `submit_btn`）。
- 选项只从**这次点开的弹层**里取。上一栏选失败后弹层还开着，混在一起会让 '南京' 出现两次
  被判歧义、整栏白丢（实测踩过，有回归）。
- 回读看显示区而不是搜索框：AntD 选中后把值写进 `.ant-select-selection-item`，
  搜索框里留着过滤残字，读 `input.value` 会把"搜索城市"当成已选值。
- 站点选项里没有资料中的值 → 橙色「需人工」，绝不硬配一个语义近似项（『应届毕业生』
  对不上『校园招聘』时就是不选）。
- 点开选中过的栏位一律黄字。

`test-forms/element-cn.html` 与 `antd-cn.html` 是对这两家框架行为的**仿真**（内联脚本复刻展开、
portal 渲染、收起只切类名等细节），跑判分时才会带 `allowCustomSelect`。**真实站点还没实测** ——
需要你在浏览器里装载后拿一两个在用页面验证，尤其是 Moka/SF 那种"选项在点开前完全不在 DOM 里"的
实现（仿真表单里没脚本，判分覆盖不到）。

## 导出某个站点的字段结构（给新站点做适配器用）

侧边栏「导出本页字段结构」是**只读**的：只取标签文本、控件类型、必填标记、站点自带的下拉候选项文案，
**不读取你填写的任何内容**——`tests/probe.test.js` 会先往表单里写入假隐私值，再断言导出结果里
既没有 `value` 键也没有那些值，作为可回归的保证。Edge 禁用 F12 时用这个入口，不需要 DevTools。

## AI 兜底（可选，默认不联网）
本地词典答不上某一栏时（`no_candidate` / `required_no_candidate` / `conflict_unresolved`），
侧边栏「AI 兜底」可以问一次外部模型。它**不是**让 AI 替你写内容，只是让 AI 从本扩展已有的槽位里
挑一个路径。三条边界写死在 `core/ai.js`，并有回归测试守着：

1. **取值不出本机**。请求体只含：页面那一栏的文字、控件类型、站点自己的下拉候选文案，
   以及槽位的路径与中文名。发送前还会用 `assertNoProfileValues()` 把整份 profile 逐值扫一遍，
   命中即拒发（`tests/ai.test.js` 会植入一个取值来证明这道闸会响）。
2. **AI 只能选路径，不能造值**。响应里的路径必须在白名单内，写进去的值永远由本地从你的资料取；
   证件号/护照/签证/薪酬期望/无犯罪记录/声明类路径根本不进白名单。
3. **结果永远黄字**。AI 选中的栏位一律 `tier=review`，且仍受「允许填写敏感字段」那道闸约束；
   两次扫描之间页面控件数变了导致下标漂移时，整条建议丢弃而不是写进别的栏位。

### Key 怎么保护

判定规则全部写在 `core/ai-security.js`（纯函数、离线单测覆盖），service worker 只是执行者：

- **默认只进 session**：Key 存 `chrome.storage.session`，且代码显式钉成 `TRUSTED_CONTEXTS` 访问级别
  （默认也是这个，写死是免得将来有人为了调试改成让注入页面的模块也读得到）。重启浏览器即失效。
- **可以记住 Key（可选，默认不勾）**：勾上后写进 `chrome.storage.local` 的**独立顶层桶 `aiSecrets`**，
  重启仍在、不必每次重录。代价说白：扩展拿不到系统钥匙串（要走 DPAPI/Keychain 就得装 native host，
  违反"纯浏览器插件"这条边界），所以它是**明文落盘**在你 Windows 账户的浏览器 profile 目录里——
  能读那个目录的人（同账户、备份盘、取证镜像）就能取出它。公用电脑或别人碰得到你的电脑就别勾。
  「清除」一次把 session 与 local 两个位置都删掉，不留"关了但还有一份"的半状态。
- **进不了会被导出的地方**：`nw:saveSettings` 走白名单，名字里带 `key/token/secret/password/auth` 的键
  一律拒收并把原因回给界面（静默吞掉只会让人以为"Key 保存成功了"）；`aiSecrets` 这个桶名本身也不在
  白名单里，所以 Key 永远不可能混进 settings。另外「导出本页字段结构」在写文件前过一次
  `findLeaksInExport()`：出现完整 Key 或 `sk-…`/`ghp_…`/`AKIA…` 这类形状就**拒绝导出**，
  且泄漏清单里只带前 6 个字符。「下载空白模板」导出的永远是空模板。
- **Origin 绑定**：录入 Key 时记下当时的 Base URL origin。之后改了 Base URL，老 Key 不会跟着发去
  新地址，必须重新录一次；「我确认把 Key 与字段名发往 `https://…`」这个勾必须打上且与当前 origin
  一致，Base URL 一变确认就作废。
  界面上那个勾**跟着存储走，不跟着鼠标走**：勾上时以后台真正记下的 origin 为准显示，
  确认被作废时勾自己灭掉。之前两者会分叉（先勾确认、再保存同一个 URL 时确认被误擦），
  结果就是"我明明勾了却报 needs_consent"——那是实现的错，不是操作的错。
  清除 Key 会连端点确认一起收掉，不留"已授权但没 Key"的空壳状态。
- **禁跟跳转**：`redirect: 'error'`。否则一次 302 就把 `Authorization` 头带到别的域去了，
  前面所有 origin 检查都白做。
- **端点形状**：必须 https（`127.0.0.1` / `localhost` 例外，供本地 Ollama/LM Studio 自测）；
  拒绝带 `user@` 的地址（看着是 A 域其实是 B 域）、拒绝带 `?query`/`#` 的地址（多半是把整条
  带 token 的链接粘进来了）、拒绝非 http(s) 协议。
- **不回显、不落日志**：Key 只做形状校验（长度/空格），界面与状态只报长度和 origin；
  保存后立即清空输入框；错误文本过 `redact()` 才返回。`tests/sidepanel.test.js` 会断言
  除 `nw:saveAiKey` 之外没有任何消息带着 Key，且页面上搜不到它。

「预览将发送的内容」与实际请求共用同一次构造，并在开头写明收件人地址——看到的就是发出去的。

**等待时长**：AI 面板里有个「等待上限（秒）」输入框，默认 **180 秒**，可填 15–900。
旧默认值 20 秒是"模型还没答完就把请求掐了"的量级，而超时是最难归因的一种失败——
用户只看到"点了没反应"。现在等待期间状态栏每秒报"已等待 N 秒 / 上限 M 秒"，
超时后那句话会直接告诉你"是多等一会儿还是少问几栏"。
同时侧边栏在请求在飞期间每 15 秒给后台发一次心跳（第一次立刻发）：
MV3 的 service worker 空闲约 30 秒会被回收，它一旦被杀，那个还在等的 fetch 的回包就永远回不来，
表现恰恰又是"没反应"。

**在仓库自带的 9 份仿真表单上，可问 AI 的缺口只有 2 栏**（Workday 的「区」「电话分机」，
而这两栏在 profile 里本来就是空的，AI 也补不了）——也就是说这套兜底在本仓库的判分集上
**增益为 0，且实测增益尚未验证**：它的价值只能在你实际遇到的自建门户上量。
先按上面的方式配好，遇到"灰·交给你手动处理"的栏位点一次「问 AI 补全缺口」，
状态栏会显示 `AI 补栏 N`。

## AI 辅助导入（另一条边界，别和上面的兜底混为一谈）

简历里"直接写内容、不写『时间：』这种对应"的写法，本地解析器会有判不动的残段。
「导入简历 Markdown」下方那个 **AI 辅助导入** 就是处理这些残段的：
它发出去的是**判不动的那几段原文**（不是整份简历），模型的作用只有一个——
说清这段该进哪个槽位，并且**逐字摘录**。

四条边界写在 `core/ai-extract.js`，`tests/ai-extract.test.js` / `tests/extract-ui.test.js` 各自守着：

1. **只发判不动的片段**：片段来自导入报告的 `unplaced` 与联系行残留，条数与总字数都有硬预算，
   后台再压一道字节上限（`EXTRACT_MAX_BYTES`）；槽位表归并成 `work.N.company` 形式，
   519 条白名单从 31KB 压到 13KB，但校验仍按完整白名单逐条走。
2. **号码类片段整段不发**：片段里出现身份证样式 / 护照号 / 银行卡连号，直接进 `blocked`，
   连预览文本里都不出现；证件号、签证、薪酬期望、声明类槽位即使在回答里出现也一律丢弃。
3. **只能逐字摘录**：返回值必须是所发片段里连续出现的原文（只允许空白差异）。
   改标点、换日期格式、调整顺序、补原文没有的词——全部按 `not_verbatim` 丢弃，
   所以这条链路不会把你的表述改成 AI 的说法。
4. **按次确认 + 勾选才写入**：没点过「预览」发送按钮是灰的；点发送会再弹一次确认，
   写明"几段、多少字节、发往哪个地址"；发过一次就重新灰掉，不记住上次的同意。
   返回结果逐条列给你（默认全勾、可取消），点「写入勾选项」才进资料，
   且默认不覆盖已有值——要覆盖得自己勾上「写入时覆盖已有值」。

模型如果把模板路径 `campus.N.org` 原样交回来，序号由本地补成"该段第一个空槽"，
并在结果里标出 `indexFilled`（这一条属于第几个经历是我们定的，不是 AI 定的）。

### 「问了 AI 却是空输出」怎么自查

这一类以前只能来回猜"是你 API 的问题还是插件的问题"。判定现在写在 `core/ai.js` 的
`interpretAiReply()`（纯函数，`tests/ai.test.js` 覆盖），界面会把**具体是哪一种空**说出来：

| 界面提示 | 含义 | 怎么办 |
|---|---|---|
| 模型只输出了思考过程，正文为空 | reasoning 模型（R1 / thinking 系列）把话写在 `reasoning_content` | 换非 reasoning 模型，或在请求里关掉思考 |
| 答案被长度上限砍断 | JSON 不完整所以解析不出来 | 少问几栏再问一次（上限已提到 2000 token） |
| 上游回了 200 但正文为空 | 模型名或兼容层不对 | 核对模型名；先看「预览」文本是否发到了那个地址 |
| 上游回的不是 JSON | Base URL 指到了网页而不是 API 根路径 | 应形如 `https://…/v1`，不要带 `/chat/completions` |
| **这个地址上没有聊天端点（HTTP 404）** | Base URL 最后一段路径没对上 | 看提示里列出的**实际请求地址**，见下一节 |
| 上游错误：… | API 自己的报错原文（已脱敏，只留 300 字） | 按报错处理（额度 / 模型不存在 / 权限） |
| AI 回了 N 字但一条都没落进白名单 | 模型答了，但格式或路径不对 | 界面附上**它原样回的前 200 字**，贴给维护者就够定位 |

响应信封已放宽：裸数组、`{"result":[…]}`、`{"data":{"matches":[…]}}`、`i/p` 简写都认；
但**路径白名单**与"只认本次问过的缺口下标"一条都没放松 —— 容错只加在"怎么读"，不加在"信什么"。

### Base URL 到底该填什么（404 就是这么来的）

大家嘴里的"Base URL"形状并不统一，而差最后一段路径的表现是一句没有任何信息量的
`http_404 Not Found`。现在扩展会把你粘的东西收敛成**候选端点**依次试（最多两个，且全部同域）：

| 你填的 Base URL | 实际 POST 到 |
|---|---|
| `https://api.x.test/v1` | `https://api.x.test/v1/chat/completions` |
| `https://api.x.test/v1/`（带尾斜杠） | 同上 |
| `https://api.x.test`（只给主机名） | 先 `/v1/chat/completions`，404 再退 `/chat/completions` |
| `https://api.x.test/v1/chat/completions`（粘了完整端点） | **原样用**，不再拼第二段 |
| `https://api.x.test/compatible-mode` | 先 `/compatible-mode/chat/completions`，404 再补 `/v1` |

规则写死在 `core/ai-security.js` 的 `chatEndpointCandidates()`，出网那段在 `core/ai-endpoint.js`，
`tests/ai-endpoint.test.js` 用假 fetch 覆盖。三条不可谈判的：

- **只有 404/405 才顺延下一个地址**。401/403/429/5xx 与超时都只发一次 ——
  非路径错误重发等于多敲一次 Key、多烧一次额度、多等一遍时间。
- **候选永远同域**：Base URL 里塞 `//evil.test`、`@evil.test` 之类都只会变成路径的一部分，
  Key 与 origin 绑定的前提不会从这里漏掉。
- **出错就把试过的地址原样列出来**，「预览」显示的也是这个完整 URL（不是 Base URL），
  不然"收件人是谁"这句话又是一句没法核对的承诺。

Azure OpenAI 那种要把 `?api-version=…` 写在地址里的形态**目前不支持**：
`normalizeBaseUrl` 直接拒绝带 query 串的 Base URL（`endpoint_has_query`），这是有意的 ——
带 token 的链接最常被整段粘进来。

### 发给模型的"可选槽位表"是压缩过的

白名单有 519 条，逐条列出来光是目录就 36KB。现在把 `work.0.company / work.1.company / …`
这种同构重复归并成 `work.N.company` + `"r":"0-3"`，206 条 / 10.8KB —— 每次少发 25KB，
模型答得也快一截。归并只改"怎么对模型说"：收回来的路径**仍按完整白名单校验**；
模型要是原样交回带 `N` 的路径，本地会补成该段第一条，并在黄字说明里写明
"这一条属于第几条经历是我们补的，不是 AI 定的"。

请求体还有构造预算（`core/ai.js` 的 `AI_MAX_BYTES`）：装不下时按
「选项文本 → 邻近标签 → 标签长度 → 少问几栏」的顺序削，削了什么在「预览」那一行如实写出来。
这条以前是**发送前的拒绝条件**，而未压缩的目录必然超 —— 于是填写侧的「问 AI」每次都在本机被判
`payload_too_large`，一个字节都没发出去过（2026-09-30 给 service worker 加集成测 `tests/ai-bridge.test.js`
时才暴露：SW 真跑一遍，才看见这条链路一直是死的）。

## 填真实信息之前：数据在哪、谁会出去

- **简历资料只在你本机**：`chrome.storage.local` 的 `profile` 键（浏览器自己的 profile 目录，
  不是云端同步 —— 扩展没有 `storage.sync` 权限）。它不会出现在任何下载物里：
  「下载空白模板」导出的是空模板，「导出本页字段结构」导出的是站点 DOM 元数据。
- **整个扩展只有一处会发网络请求**：service worker 里那个 AI 调用。
  另外两处 `fetch` 都是 `chrome.runtime.getURL(…)` 读扩展自己打包的 JSON。
  不配 Key、不点确认，就一个字节都不出门。
- **两条 AI 链路各守各的边界**：填写侧只发页面字段名（发送前 `assertNoProfileValues` 逐值自检，命中即拒发）；
  导入侧只发本地判不动的残段原文（逐字摘录、按次确认、号码样式整段拒发）。
- **Key**：默认只在 `chrome.storage.session`（重启即失效）；勾"记住"才进 `local` 的独立 `aiSecrets` 桶，
  那是明文落盘，代价与适用场景写在上面那节。Key 与 origin 绑定、禁跟跳转、界面不回显、不进 settings、不进导出。
- **界面注入**：`tests/xss.test.js` 把 `<img onerror=…>` 塞进简历取值、站点标签、回读值、缺口原因与 AI 回显，
  断言扩展页面里不出现可执行节点（同时原文不能被吞掉）。这条很重要：
  侧边栏是插件页面，能读整份简历，任何一个渲染点漏转义都等于开了一条外传通道。
- **权限面要如实说**：`host_permissions` 与 content script 是 `http/https *`，也就是说这个扩展
  *有能力*读任意站点的 DOM（它必须能在任意招聘网站工作）。代码层面它只在被消息驱动时才扫描，
  不驻留定时器、不自动读取。想要更严，可以把注入改成"只在你点图标的那个标签页按需注入"（`activeTab`），
  这是一项待办改动，现在的实现还没做。
