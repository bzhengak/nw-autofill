# 网申自动填写（nw-autofill）

Chrome / Edge MV3 扩展。在公司自建网申页面上，按你维护的一份标准简历把客观字段一次填好，
填不出的明确标出来交给你决定。**不替你提交、不解验证码、不做测评、不上传附件。**

当前进度：**P0 完成 + P1 的 Markdown 导入完成**。可以加载试用；PDF 导入与多模板切换在下一轮，
真实招聘站点的控件适配（P2）尚未开始。

## 装载试用

1. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选择本仓库根目录（能看到 `manifest.json` 的那一层）
4. 打开某个网申页面 → 点工具栏图标 → 侧边栏「导入简历 Markdown」粘贴简历全文 → 解析并填入
   （不想用导入的，可以「下载空白模板」拿到全部 526 个可填项，手填后在 JSON 区保存）
5. 回到网申页面点「扫描并填写」；不满意可点「回滚本次填写」

> P0 阶段简历数据要靠手工维护 JSON。Markdown / PDF 自动解析在 P1。

## 颜色含义

- 绿：高置信，已填入，仍需你扫一眼
- 黄：填了但置信度不足或属敏感字段，**请复核**
- 红：尝试写入但页面回读不一致（受控组件没吃进去）
- 灰：交给你手动处理（主观题、附件、验证码、无对应资料）

## 导出某个站点的字段结构（给新站点做适配器用）

侧边栏「导出本页字段结构」是**只读**的：只取标签文本、控件类型、必填标记、站点自带的下拉候选项文案，
**不读取你填写的任何内容**——`tests/probe.test.js` 会先往表单里写入假隐私值，再断言导出结果里
既没有 `value` 键也没有那些值，作为可回归的保证。Edge 禁用 F12 时用这个入口，不需要 DevTools。

## AI 兜底（可选，默认不联网）

本地词典答不上某一栏时（`no_candidate` / `required_no_candidate` / `conflict_unresolved`），
侧边栏「AI 兜底」可以问一次外部模型。它**不是**让 AI 替你写内容，只是让 AI 从本扩展已有的槽位里
挑一个路径。三条边界写死在 `core/ai.js`，并有回归测试守着：

1. **取值不出本机**。请求体只含：页面那一栏的文字、控件类型、站点自己的下拉候选文案，
   以及槽位的路径与中文名。发送前还会用 `assertNoProfileValues()` 把整份 profile 逐值扫一遍，
   命中即拒发（`tests/ai.test.js` 会植入一个取值来证明这道闸会响）。
2. **AI 只能选路径，不能造值**。响应里的路径必须在白名单内，写进去的值永远由本地从你的资料取；
   证件号/护照/签证/薪酬期望/无犯罪记录/声明类路径根本不进白名单。
3. **结果永远黄字**。AI 选中的栏位一律 `tier=review`，且仍受「允许填写敏感字段」那道闸约束；
   两次扫描之间页面控件数变了导致下标漂移时，整条建议丢弃而不是写进别的栏位。

### Key 怎么保护

判定规则全部写在 `core/ai-security.js`（纯函数、离线单测覆盖），service worker 只是执行者：

- **只进 session**：Key 存 `chrome.storage.session`，且代码显式钉成 `TRUSTED_CONTEXTS` 访问级别
  （默认也是这个，写死是免得将来有人为了调试改成让注入页面的模块也读得到）。重启浏览器即失效。
- **进不了持久化设置**：`nw:saveSettings` 走白名单，名字里带 `key/token/secret/password/auth` 的键
  一律拒收，并把拒收原因回给界面——静默吞掉只会让人以为"Key 保存成功了"。
- **Origin 绑定**：录入 Key 时记下当时的 Base URL origin。之后改了 Base URL，老 Key 不会跟着发去
  新地址，必须重新录一次；「我确认把 Key 与字段名发往 `https://…`」这个勾必须打上且与当前 origin
  一致，Base URL 一变勾就作废。
- **禁跟跳转**：`redirect: 'error'`。否则一次 302 就把 `Authorization` 头带到别的域去了，
  前面所有 origin 检查都白做。
- **端点形状**：必须 https（`127.0.0.1` / `localhost` 例外，供本地 Ollama/LM Studio 自测）；
  拒绝带 `user@` 的地址（看着是 A 域其实是 B 域）、拒绝带 `?query`/`#` 的地址（多半是把整条
  带 token 的链接粘进来了）、拒绝非 http(s) 协议。
- **不回显、不落日志**：Key 只做形状校验（长度/空格），界面与状态只报长度和 origin；
  保存后立即清空输入框；错误文本过 `redact()` 才返回。`tests/sidepanel.test.js` 会断言
  除 `nw:saveAiKey` 之外没有任何消息带着 Key，且页面上搜不到它。

「预览将发送的内容」与实际请求共用同一次构造，并在开头写明收件人地址——看到的就是发出去的。

**在仓库自带的 9 份仿真表单上，可问 AI 的缺口只有 2 栏**（Workday 的「区」「电话分机」，
而这两栏在 profile 里本来就是空的，AI 也补不了）——也就是说这套兜底在本仓库的判分集上
**增益为 0，且实测增益尚未验证**：它的价值只能在你实际遇到的自建门户上量。
先按上面的方式配好，遇到"灰·交给你手动处理"的栏位点一次「问 AI 补全缺口」，
状态栏会显示 `AI 补栏 N`。

## 开发

```bash
npm install            # 只装 jsdom，用于离线评测
npm test               # core/ 纯函数单测
npm run hit            # 在 test-forms/ 仿真表单上跑命中率判分
npm run check          # 两者一起
```

目录分层与依赖方向见 `UPSTREAM.md`；需求与验收标准见 `docs/REQUIREMENTS.md`。
