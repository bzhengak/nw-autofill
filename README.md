# 网申自动填写（nw-autofill）

Chrome / Edge MV3 扩展。在公司自建网申页面上，按你维护的一份标准简历把客观字段一次填好，
填不出的明确标出来交给你决定。**不替你提交、不解验证码、不做测评、不上传附件。**

当前进度：P0 + P1 的 Markdown/AI 辅助导入、P2 的中文框架家族（Element UI / AntD / Moka）、
P3 的 SF / Workday 适配与 AI 兜底都已落地，另有中英两份值与 217 条离线回归 + 191/191 判分。
**但这套扩展还没在真实浏览器里跑通过** —— 所有站点结论来自 `test-forms/` 仿真 + 你导出的页面结构，
第一次实测请以"预览 → 逐条核对 → 再写入"的方式用。

## 装载试用

1. Chrome 打开 `chrome://extensions/`，Edge 打开 `edge://extensions/`
2. 右上角开启「开发者模式」
3. 点「加载已解压的扩展程序」，选择本仓库根目录（能看到 `manifest.json` 的那一层）
4. 打开某个网申页面 → 点工具栏图标 → 侧边栏「导入简历 Markdown」粘贴简历全文 → 解析并填入
   （不想用导入的，可以「下载空白模板」拿到全部 526 个可填项，手填后在 JSON 区保存）
5. 回到网申页面点「扫描并填写」；不满意可点「回滚本次填写」

**改完代码怎么确认重载真的生效了**：侧边栏顶栏那行会报 `构建 <日期>-<序号>`（唯一来源是 `core/build.js`）。
如果它显示"后台没跟上：…"，说明面板是新的、MV3 的 service worker 还是旧的那一份
（旧 worker 挂着连接时不会立刻退场，这是本扩展最常见的"我明明重载了"成因）。
修法：在 `chrome://extensions` 把本扩展的开关**关掉再打开**，然后关掉侧边栏重开。
只有探针导出物里的 `probeBuild` 与你看到的构建号一致，那份 JSON 才对得上当前代码。

## 颜色含义

- 绿：高置信，已填入，仍需你扫一眼
- 黄：填了但置信度不足或属敏感字段，**请复核**
- 红：尝试写入但页面回读不一致（受控组件没吃进去）
- 灰：交给你手动处理（主观题、附件、验证码、无对应资料）

## 映射表先行：写入前的那一道确认（默认开着）

侧边栏「本页映射表」把这一页**每一栏**摊成一行：页面这一栏（标签 / 来源 / 板块 / 选项 / 说明）、
我们的判定（判给哪个资料槽位，或为什么没定）、凭什么（来历 + 证据 + 置信 + 说明）、
现在是谁写的（我们上一轮写的 / 站点或你自己填的 / 空的）、改判（下拉 + 一句理由）。

开着「映射表先行」时：

- 顶部那枚按钮变成**「扫描并出映射表」**，点它不会动页面一个字节；
- 真正落笔只认**「按此映射填写」**那一个钮；
- 表顶那句话会说清这一轮做了什么：`映射表先行：这一轮只出了这张表，页面一个字节都没改。`

改判只做一件事：决定**这一格是什么**。取值仍来自你的资料 —— 资料里那一栏空着，
表里就照旧说"钉住了槽位但资料是空的"，不会拿别的栏位顶替。下拉里只列资料中真实存在的槽位
（先输关键词筛，默认给前 40 个）；自造路径在后台就被拒，并当场念出理由。
「这一栏不自动填」是另一种决定：这一栏进「需要你处理」，原因写 `这一栏你在映射表里勾了「不自动填」`。

改判能记住：**勾「改判同时记住到本站」**才会落盘（`chrome.storage.local.nwSiteRules`，
按站点分桶、只在这一站生效、里面只有"栏位长什么样 → 槽位名"，没有你的取值）。
不勾就是本轮生效，关页就没 —— 面板不会替你偷偷记。规则按**栏位指纹**认栏，
所以 SPA 重建 DOM、换一步表单都还能命中；代价是同页两栏自述完全相同时共用一条规则，
这种情况表里会标 `这一页有 N 栏自述完全相同`，并且那一栏强制黄字。

表上方的「计划校验」是落笔前的整页算术，每条都带下一步：资料有 3 段而页面只排了 1 组、
页面有 3 组而资料只填了 1 段、同一个只能填一次的槽位被两栏认领、必填栏没安排值、
整页一栏都不写（附本轮原因分布）。诊断包里的「映射表」那段给的是脱敏视图：
只有页面文字、槽位名与依据，屏幕上那份的回读值不进文件。

关掉的办法：取消勾选「映射表先行」。那一格关着时按钮回到「扫描并填写」（直接写），
映射表照旧出，只是不再拦着写入。

## 认选项：下拉里该选哪一项（默认不发出你的任何取值）

有些栏位我们把"它是哪一栏"判对了，却对不上页面给的那一项：页面问「是否全日制」而资料里存的是「全日制」；
港页写 `Right of Abode Holder` / `Holder of IANG`，而资料里写「永久居民」「IANG（内地应届毕业生留港计划）」。
这类栏位在映射表里标着「需要选一项」，点**认选项（下拉里该选哪一项）**问一次。

两条通路，默认走第一条：

 · **只发页面的话**：把这一栏的选项文字发给模型，让它给每一项归一个**封闭代号**
   （`IANG` / `HK_PERMANENT_RESIDENT` / `FULL_TIME`…）；你资料里那条值在**本机**折成同一个代号，
   两边相同才落这一项。折不出代号、或有两项都说得通 → 不猜，继续留在「需要你处理」。
 · **允许 AI 看取值**（「填写授权」里的勾选框，默认关）：把"我打算写进这一栏的那条值"一起发出去，
   模型直接挑那一项。勾了就能用，不必逐次确认；每次回答都会说明"这次发了哪几栏的取值"（只报栏名，不报值）。
   **永不出门**：证件号、护照号、电话（含区号与分机）、姓名与单独的姓/名（本人、家属、紧急联系人、推荐人、内推人）、
   微信号、经历正文与声明勾选。被拦下的栏位逐条列出原因，不会静默跳过。

两种模式都只许模型**指认页面已有的那一项**：写进控件的是页面自己的文案与码值，模型给的任何文字都不进值。
工作许可 / 签证类别这类是一句合规声明，即使不算敏感也保持黄字核对。

顺带一条口径修正：港站的「Work Permit」通常不是 Yes/No，而是**在港签证/进入许可类别**的下拉
（TTPS / GEP / ASMTP / IANG / QMAS / 受养人 / 学生 / 永居…，词表见
[IMMD Visas / Entry Permits](https://www.immd.gov.hk/eng/forms/hk-visas.html)）。资料里那一栏现在是枚举。
判据与取舍记录在 [docs/AI-VALUE-ALIGNMENT.md](docs/AI-VALUE-ALIGNMENT.md)。

## 补经历行（需要你显式授权，默认关着）

分段经历的页面常常先只给一段，旁边一枚「+ 添加一段」。资料里有三段时，后两段就没地方写 ——
映射表上方的计划校验会说这一句（`资料里有 3 段「实习经历」，这一页只排到第 1 组…`）。
要我们替你点那枚加号，就去「填写授权」里勾 **允许补经历行**，然后照旧点「按此映射填写」。

三条限制一道不能少：

- **只在真的要写的那一跳点**：预览/出表阶段一个点击都不发（`dryRun` 单独也挡得住）；
- **每轮最多 3 段**：需要 10 段也只点 3 次，剩下的自己去点或再来一轮；
- **点了没长出来立刻停**：一次点击必须让那一节里扫得到的栏位变多，否则不再连点 ——
  连点一个没有反馈的按钮是在页面上制造未知状态。

只点**这一节容器里**、文字能确认是"加一段"的那枚控件；文字里带 删除/提交/保存/下一步/上传/登录/验证码
的一律不点（黑名单一票否决）。找不到加号就说找不到，绝不猜旁边的按钮。
每一轮补了几行、卡在哪一节，都写在「本次结果」的 `rowExpansion` 里（界面上是表上方那句话），不是日志里埋着。

## 中英两份值（英文网申用得上）

「分类编辑」顶部有「中文 / English」两枚按钮，**只翻这个编辑区**：同一栏位在英文模式下显示英文名、
写英文值，切回中文又是原来的样子；这个选择会记住（`settings.editorLang`），重开面板不会把你补到一半弹回中文。

两份值存在同一份简历里的两个桶：中文在 `education.0.school`，英文在 `en.education.0.school`
（`profile.en` 是一棵同结构子树）。**保存只写当前语言的桶** —— 补英文不会把中文值盖掉，
清掉英文也不会连带清空中文。

不是每栏都要抄两遍，下面这些**两种语言共用一份**，英文模式下直接显示、直接写：

- 语言中性的控件类型：日期、数字、邮箱、电话、链接、文件等；
- 值里本来就没有汉字的：拼音姓名 `Zhang` / `Wei`、`GPA 3.8`、`2021-09`；
- 站点自己会翻译的枚举：英文模式下选项显示 `Male`，**存进简历的仍是规范值 `男`**
  （把 `Male` 写回去会让选项匹配、体检、回读三处一起错乱）；
- 栏位名以 `En` 结尾的（`education.0.schoolEn` 学校英文名、`basics.nameEn` 英文姓名、
  `contact.addressEn` 英文地址）：这一栏的取值**本身就是英文**，不再套第二层 `en.`。

想在编辑器外面手写英文也可以，而且现在看得见该写在哪：**「下载空白模板」和「导出资料 JSON」
都带着完整的英文骨架**（537 个槽位里 317 个需要英文写法的，都在 `en` 子树里摆成空串；
列表项预先补成齐的，不会序列化出 `null` 洞）。老资料里 `en` 只有几栏的，在落库
（`nw:saveProfile`）与面板显示时会自动补齐 —— 只补空缺，绝不盖掉你写过的英文值。
「简历数据」那行会报 `英文写法：8/12 栏已补`，这个分母按"中文侧真的填了汉字"来算，
空白模板不会凭空催你补英文。

真正需要补的是"中文有值、英文没值"的那几栏：编辑区会给它们一条橙色标记，顶部的计数告诉你还缺几栏
（灰色占位符就是那一栏的中文写法，照着翻即可）。

填写时读哪一份由**页面**决定，不由编辑区的开关决定：`core/matcher.js` 先看这一页标签是中文还是英文
（`detectPageLanguage`），英文页取 `en.` 值；标签里明写"中文"的栏位（港企常见的「姓名(中文)」）仍然取中文值。

**缺英文值时默认不写**，那一栏进「待你处理」，面板会说明"这一页是英文表单，N 个槽位只有中文写法，
已故意留空"——把「南京大学」写进 `School Name` 属于典型的"看起来填好了、其实全错"。
赶时间可以在「分类编辑」底部勾上「英文表单遇到只有中文写法的栏位：写中文并标黄」
（`settings.enMissingMode = 'zh_yellow'`）降级：会写中文，但一律黄字并写明"写的是中文值"。

## 这一页为什么填不上（一份「诊断包」）

「资料与设置」那一屏有一个按钮：**生成诊断包（只读，不改页面）**。一份 JSON 里三段，各答一个问题：

- **页面结构**（探针）：标签到底在 DOM 哪儿、页面用什么组件库、有没有 iframe。给新站点写适配器要的是这份。
- **没填的与选项**：这一栏为什么没填上、页面上可选项到底是什么。每个没填的控件带一条记录，
  带选项的控件会把 **选项文案 ↔ 提交码值** 成对列出来（例如「是」↔ `Y`、「Python」↔ `PY`），
  还有当前已选项和原因（`no_candidate` / `custom_control` / `option_missing`…）。
  勾上「把已填的也带上」可以把成功的对照一起看。
- **映射表**：这一页每一栏判给了谁、凭什么、要不要动。**这一段不含任何取值**（生成时当场检查，命中就拒绝出包）。

哪一段没进来，`missing` 里会写明原因（比如这一页还没扫过、那个框里没有表单控件），
不会给你一个"看着完整其实缺一段"的文件。没点过「扫描并填写」就直接生成也安全：
内容脚本先 `dryRun` 只读算一遍计划，不改页面任何一个字节。

以前这三样各占一个板块、共 9 个按钮；2026-10-04 收成一个（同一批还把面板分成「填这张表 / 资料与设置」两屏）。


## 一页里有好几个「Name」怎么办（板块归属）

英文网申页常见这种形状：项目、实习、证书、家庭成员……每个板块里都有一栏就叫 `Name`。
一个词决定不了它是谁的名称，所以我们**按板块定栏位，不按资料顺序轮值**：

- 别名表里不放裸词 `name` —— 它只属于「姓名」。要命中证书名称，标签得写成
  `Certificate Name` / `证书名称` 这类带定语的说法（`School Name` 就是 `School Name`）。
- 板块标题从 DOM 里"一个容器排着几栏，其中不含控件的那一支短文本"取，不看标签文字；
  取到了，`Name` 在证书区就拿证书名称，在基本信息区才拿姓名。
- 取不到、而同一个光秃秃的词在页面上出现两次以上 → **这一栏不写**，进「需要你处理」，
  并把候选板块念给你听。
- 标签点名的那一栏（例如 `Address` ≡ 现居住地址）在资料里是空的 → **留空并说明**，
  绝不拿别的栏位的值顶上；也不会把 `undefined` 这类字样写进页面（宁可不写）。
- 想知道某一栏被我们判给了哪个板块：「没填的字段与选项」导出里每行都带
  `sectionTitle` / `sectionHint` / `sectionSource` 三列。

## 点开自定义下拉（需要你显式授权）

Element UI / AntD / `role=combobox` 这类下拉没有 `<select>`，选项是点击后渲染到 body 末端的弹层，
打字不会选中任何值。侧边栏「允许点开自定义下拉并选中」勾上后才会真的点击页面控件；**默认关**。

边界（`dom/select-opener.js` + `dom/safety.js`）：

- 「什么算选择控件触发器」在 `SELECT_TRIGGER_SELECTOR` 里定义一次，扫描、点击闸门、opener 共用；
  闸门仍然生效：提交、导航、附件、其它按钮一律不点（判分表单里 `mustNotTouch` 盯着 `submit_btn`）。
- 选项只从**这次点开的弹层**里取。上一栏选失败后弹层还开着，混在一起会让 '南京' 出现两次
  被判歧义、整栏白丢（实测踩过，有回归）。
- 回读看显示区而不是搜索框：AntD 选中后把值写进 `.ant-select-selection-item`，
  搜索框里留着过滤残字，读 `input.value` 会把"搜索城市"当成已选值。
- 站点选项里没有资料中的值 → 橙色「需人工」，绝不硬配一个语义近似项（『应届毕业生』
  对不上『校园招聘』时就是不选）。
- 点开选中过的栏位一律黄字。

`test-forms/element-cn.html` 与 `antd-cn.html` 是对这两家框架行为的**仿真**（内联脚本复刻展开、
portal 渲染、收起只切类名等细节），跑判分时才会带 `allowCustomSelect`。**真实站点还没实测** ——
需要你在浏览器里装载后拿一两个在用页面验证，尤其是 Moka/SF 那种"选项在点开前完全不在 DOM 里"的
实现（仿真表单里没脚本，判分覆盖不到）。

## 导出某个站点的字段结构（给新站点做适配器用）

诊断包里「页面结构」那一段是**只读**的：只取标签文本、控件类型、必填标记、站点自带的下拉候选项文案，
**不读取你填写的任何内容**——`tests/probe.test.js` 会先往表单里写入假隐私值，再断言导出结果里
既没有 `value` 键也没有那些值，作为可回归的保证。Edge 禁用 F12 时用这个入口，不需要 DevTools。

## AI 兜底（可选，默认不联网）
本地词典答不上某一栏时（`no_candidate` / `required_no_candidate` / `conflict_unresolved`），
侧边栏「AI 兜底」可以问一次外部模型。它**不是**让 AI 替你写内容，只是让 AI 从本扩展已有的槽位里
挑一个路径。三条边界写死在 `core/ai.js`，并有回归测试守着：

1. **取值不出本机**。请求体只含**页面档案**：那一栏的标签与说明文字、所在板块、控件类型、
   站点自己的下拉候选（`文案=码值`）、邻近标签，以及槽位的路径与中文名。发送前还会用
   `assertNoProfileValues()` 把整份 profile 逐值扫一遍，命中即拒发（`tests/ai.test.js` 会植入一个取值来证明这道闸会响）。
2. **AI 只能选路径，不能造值**。响应里的路径必须在白名单内，写进去的值永远由本地从你的资料取；
   证件号/护照/签证/薪酬期望/无犯罪记录/声明类路径根本不进白名单。
3. **档位按敏感与否分**（2026-10-02 改的口径：用户每栏都会自己核对，不再一律压黄字）。
   AI 指认的非敏感槽位按正常 `auto` 走绿字，但 `aiChosen` 标记与〔AI 选路〕角标保留，撤销与审计认得这一笔；
   敏感槽位仍是 `review`，且仍受「允许填写敏感字段」那道闸约束。两次扫描之间页面控件数变了导致下标漂移时，
   整条建议丢弃而不是写进别的栏位。
4. **两道确认闸**：`aiConsentOrigin` 管"Key 与字段名发去哪个 AI 地址"，`aiSiteConsent` 管"这一站的字段名可以发"。
   换一个招聘站点会再问一次（勾一次记一站），换 AI 地址则两本账一起作废。
   站点由后台按标签页自己查，查不到（`chrome://`、本地文件）就拒发。

### Key 怎么保护

判定规则全部写在 `core/ai-security.js`（纯函数、离线单测覆盖），service worker 只是执行者：

- **默认只进 session**：Key 存 `chrome.storage.session`，且代码显式钉成 `TRUSTED_CONTEXTS` 访问级别
  （默认也是这个，写死是免得将来有人为了调试改成让注入页面的模块也读得到）。重启浏览器即失效。
- **可以记住 Key（可选，默认不勾）**：勾上后写进 `chrome.storage.local` 的**独立顶层桶 `aiSecrets`**，
  重启仍在、不必每次重录。代价说白：扩展拿不到系统钥匙串（要走 DPAPI/Keychain 就得装 native host，
  违反"纯浏览器插件"这条边界），所以它是**明文落盘**在你 Windows 账户的浏览器 profile 目录里——
  能读那个目录的人（同账户、备份盘、取证镜像）就能取出它。公用电脑或别人碰得到你的电脑就别勾。
  「清除」一次把 session 与 local 两个位置都删掉，不留"关了但还有一份"的半状态。
- **进不了会被导出的地方**：`nw:saveSettings` 走白名单，名字里带 `key/token/secret/password/auth` 的键
  一律拒收并把原因回给界面（静默吞掉只会让人以为"Key 保存成功了"）；`aiSecrets` 这个桶名本身也不在
  白名单里，所以 Key 永远不可能混进 settings。另外「生成诊断包」在复制/落盘前过一次
  `findLeaksInExport()`：出现完整 Key 或 `sk-…`/`ghp_…`/`AKIA…` 这类形状就**拒绝导出**，
  且泄漏清单里只带前 6 个字符。「下载空白模板」导出的永远是空模板。
- **Origin 绑定**：录入 Key 时记下当时的 Base URL origin。之后改了 Base URL，老 Key 不会跟着发去
  新地址，必须重新录一次；「我确认把 Key 与字段名发往 `https://…`」这个勾必须打上且与当前 origin
  一致，Base URL 一变确认就作废。
  界面上那个勾**跟着存储走，不跟着鼠标走**：勾上时以后台真正记下的 origin 为准显示，
  确认被作废时勾自己灭掉。之前两者会分叉（先勾确认、再保存同一个 URL 时确认被误擦），
  结果就是"我明明勾了却报 needs_consent"——那是实现的错，不是操作的错。
  清除 Key 会连端点确认一起收掉，不留"已授权但没 Key"的空壳状态。
- **禁跟跳转**：`redirect: 'error'`。否则一次 302 就把 `Authorization` 头带到别的域去了，
  前面所有 origin 检查都白做。
- **端点形状**：必须 https（`127.0.0.1` / `localhost` 例外，供本地 Ollama/LM Studio 自测）；
  拒绝带 `user@` 的地址（看着是 A 域其实是 B 域）、拒绝带 `?query`/`#` 的地址（多半是把整条
  带 token 的链接粘进来了）、拒绝非 http(s) 协议。
- **不回显、不落日志**：Key 只做形状校验（长度/空格），界面与状态只报长度和 origin；
  保存后立即清空输入框；错误文本过 `redact()` 才返回。`tests/sidepanel.test.js` 会断言
  除 `nw:saveAiKey` 之外没有任何消息带着 Key，且页面上搜不到它。

「预览将发送的内容」与实际请求共用同一次构造，并在开头写明收件人地址——看到的就是发出去的。

**等待时长**：AI 面板里有个「等待上限（秒）」输入框，默认 **180 秒**，可填 15–900。
旧默认值 20 秒是"模型还没答完就把请求掐了"的量级，而超时是最难归因的一种失败——
用户只看到"点了没反应"。现在等待期间状态栏每秒报"已等待 N 秒 / 上限 M 秒"，
超时后那句话会直接告诉你"是多等一会儿还是少问几栏"。
同时侧边栏在请求在飞期间每 15 秒给后台发一次心跳（第一次立刻发）：
MV3 的 service worker 空闲约 30 秒会被回收，它一旦被杀，那个还在等的 fetch 的回包就永远回不来，
表现恰恰又是"没反应"。

**在仓库自带的 9 份仿真表单上，可问 AI 的缺口只有 2 栏**（Workday 的「区」「电话分机」，
而这两栏在 profile 里本来就是空的，AI 也补不了）——也就是说这套兜底在本仓库的判分集上
**增益为 0，且实测增益尚未验证**：它的价值只能在你实际遇到的自建门户上量。
先按上面的方式配好，遇到"灰·交给你手动处理"的栏位点一次「问 AI 补全缺口」，
状态栏会显示 `AI 补栏 N`。

## AI 辅助导入（另一条边界，别和上面的兜底混为一谈）

简历里"直接写内容、不写『时间：』这种对应"的写法，本地解析器会有判不动的残段。
「导入简历 Markdown」下方那个 **AI 辅助导入** 就是处理这些残段的：
它发出去的是**判不动的那几段原文**（不是整份简历），模型的作用只有一个——
说清这段该进哪个槽位，并且**逐字摘录**。

四条边界写在 `core/ai-extract.js`，`tests/ai-extract.test.js` / `tests/extract-ui.test.js` 各自守着：

1. **只发判不动的片段**：片段来自导入报告的 `unplaced` 与联系行残留，条数与总字数都有硬预算，
   后台再压一道字节上限（`EXTRACT_MAX_BYTES`）；槽位表归并成 `work.N.company` 形式，
   519 条白名单从 31KB 压到 13KB，但校验仍按完整白名单逐条走。
2. **号码类片段整段不发**：片段里出现身份证样式 / 护照号 / 银行卡连号，直接进 `blocked`，
   连预览文本里都不出现；证件号、签证、薪酬期望、声明类槽位即使在回答里出现也一律丢弃。
3. **只能逐字摘录**：返回值必须是所发片段里连续出现的原文（只允许空白差异）。
   改标点、换日期格式、调整顺序、补原文没有的词——全部按 `not_verbatim` 丢弃，
   所以这条链路不会把你的表述改成 AI 的说法。
4. **按次确认 + 勾选才写入**：没点过「预览」发送按钮是灰的；点发送会再弹一次确认，
   写明"几段、多少字节、发往哪个地址"；发过一次就重新灰掉，不记住上次的同意。
   返回结果逐条列给你（默认全勾、可取消），点「写入勾选项」才进资料，
   且默认不覆盖已有值——要覆盖得自己勾上「写入时覆盖已有值」。

模型如果把模板路径 `campus.N.org` 原样交回来，序号由本地补成"该段第一个空槽"，
并在结果里标出 `indexFilled`（这一条属于第几个经历是我们定的，不是 AI 定的）。

### 「问了 AI 却是空输出」怎么自查

这一类以前只能来回猜"是你 API 的问题还是插件的问题"。判定现在写在 `core/ai.js` 的
`interpretAiReply()`（纯函数，`tests/ai.test.js` 覆盖），界面会把**具体是哪一种空**说出来：

| 界面提示 | 含义 | 怎么办 |
|---|---|---|
| 模型只输出了思考过程，正文为空 | reasoning 模型（R1 / thinking 系列）把话写在 `reasoning_content` | 换非 reasoning 模型，或在请求里关掉思考 |
| 答案被长度上限砍断 | JSON 不完整所以解析不出来 | 少问几栏再问一次，或把「回答长度上限」调大（默认 4000 token） |
| 上游回了 200 但正文为空 | 模型名或兼容层不对 | 核对模型名；先看「预览」文本是否发到了那个地址 |
| 上游回的不是 JSON | Base URL 指到了网页而不是 API 根路径 | 应形如 `https://…/v1`，不要带 `/chat/completions` |
| **这个地址上没有聊天端点（HTTP 404）** | Base URL 最后一段路径没对上 | 看提示里列出的**实际请求地址**，见下一节 |
| 上游错误：… | API 自己的报错原文（已脱敏，只留 300 字） | 按报错处理（额度 / 模型不存在 / 权限） |
| AI 回了 N 字但一条都没落进白名单 | 模型答了，但格式或路径不对 | 界面附上**它原样回的前 200 字**，贴给维护者就够定位 |

响应信封已放宽：裸数组、`{"result":[…]}`、`{"data":{"matches":[…]}}`、`i/p` 简写都认；
但**路径白名单**与"只认本次问过的缺口下标"一条都没放松 —— 容错只加在"怎么读"，不加在"信什么"。

### Base URL 到底该填什么（404 就是这么来的）

大家嘴里的"Base URL"形状并不统一，而差最后一段路径的表现是一句没有任何信息量的
`http_404 Not Found`。现在扩展会把你粘的东西收敛成**候选端点**依次试（最多两个，且全部同域）：

| 你填的 Base URL | 实际 POST 到 |
|---|---|
| `https://api.x.test/v1` | `https://api.x.test/v1/chat/completions` |
| `https://api.x.test/v1/`（带尾斜杠） | 同上 |
| `https://api.x.test`（只给主机名） | 先 `/v1/chat/completions`，404 再退 `/chat/completions` |
| `https://api.x.test/v1/chat/completions`（粘了完整端点） | **原样用**，不再拼第二段 |
| `https://api.x.test/compatible-mode` | 先 `/compatible-mode/chat/completions`，404 再补 `/v1` |

规则写死在 `core/ai-security.js` 的 `chatEndpointCandidates()`，出网那段在 `core/ai-endpoint.js`，
`tests/ai-endpoint.test.js` 用假 fetch 覆盖。三条不可谈判的：

- **只有 404/405 才顺延下一个地址**。401/403/429/5xx 与超时都只发一次 ——
  非路径错误重发等于多敲一次 Key、多烧一次额度、多等一遍时间。
- **候选永远同域**：Base URL 里塞 `//evil.test`、`@evil.test` 之类都只会变成路径的一部分，
  Key 与 origin 绑定的前提不会从这里漏掉。
- **出错就把试过的地址原样列出来**，「预览」显示的也是这个完整 URL（不是 Base URL），
  不然"收件人是谁"这句话又是一句没法核对的承诺。

Azure OpenAI 那种要把 `?api-version=…` 写在地址里的形态**目前不支持**：
`normalizeBaseUrl` 直接拒绝带 query 串的 Base URL（`endpoint_has_query`），这是有意的 ——
带 token 的链接最常被整段粘进来。

### 「测一下连接」为什么会说"路是通的，只是慢"

非流式响应有一个物理事实：**整段答案生成完之前，服务端一个字节都不发**。
所以"15 秒没回话"有两种完全不同的解释 —— 路径不通，或者模型还在想。
插件用三发按需递进的探测把它们分开：

1. 与真请求同一条链路，正文写死 `ping`，**`max_tokens` 给 1**（第一版沿用真请求的 2000，
   reasoning 模型光思考就超过 15 秒，自检把"它在想"误报成了"对端没回话"）；
2. 只有第 1 发连 HTTP 状态都没拿到时，做一次**不带任何头部与凭据的 GET**（同一 origin 根路径）：
   连它都不通 = 这台机器到不了那个域，用量必然是 0；
3. 域名通而第 1 发仍沉默时，再用 `stream: true` + 1 token 摸一次第一个字节 ——
   摸到了就是 `holding_response`（路通、对端在生成，这是慢不是不通），摸不到才是 `no_first_byte`。

「回答长度上限」（`settings.aiMaxOutput` → 请求里的 `max_tokens`，默认 4000，可填 500–16000）
就是配合这一条用的：reasoning 模型把**思考链也算进 max_tokens**，
给小了会出现"正文是空的"或"JSON 被砍断"，看起来都像"AI 没建议"。用 R1 / QwQ / Qwen3 思考模式建议 6000 起。

### 真请求默认走流式（`aiStream`，可关）

既然自检能看到"非流式 15 秒零字节、流式立刻开始回话"，真请求就没有理由继续用非流式。
现在默认 `stream: true`，正文按 SSE 帧拼回完整答案后，交给**同一个** `interpretAiReply` 判定 ——
空正文 / 只有思考 / 被截断这些结论不会因为换了收法而分叉。换来的是三件以前看不见的事：

- 第一个字节什么时候到（写进时间线，相对**请求发出**，不是相对响应头）；
- 中途超时或取消时**已经收到多少字** —— "它一个字都没回"和"它回了一半卡住"是两种病；
- 服务商不认 `stream` 参数时**自动退回普通收法再试一次**（只有 400/422、拿不到 body 流、
  SSE 读不动这几种形状才退；401/404/429/5xx 与超时都不退，多打一发只是浪费额度），
  退回过就在结果那一行说明"这次是换了收法才通的"。

关掉它只有一种理由：你想看非流式的一次性响应。副作用很明确 —— "慢"和"不通"重新变得同形。

### 发给模型的"可选槽位表"是压缩过的

白名单有 519 条，逐条列出来光是目录就 36KB。现在把 `work.0.company / work.1.company / …`
这种同构重复归并成 `work.N.company` + `"r":"0-3"`，206 条 / 10.8KB —— 每次少发 25KB，
模型答得也快一截。归并只改"怎么对模型说"：收回来的路径**仍按完整白名单校验**；
模型要是原样交回带 `N` 的路径，本地会补成该段第一条，并在黄字说明里写明
"这一条属于第几条经历是我们补的，不是 AI 定的"。

请求体还有构造预算（`core/ai.js` 的 `AI_MAX_BYTES`）：装不下时按
「选项文本 → 邻近标签 → 标签长度 → 少问几栏」的顺序削，削了什么在「预览」那一行如实写出来。
这条以前是**发送前的拒绝条件**，而未压缩的目录必然超 —— 于是填写侧的「问 AI」每次都在本机被判
`payload_too_large`，一个字节都没发出去过（2026-09-30 给 service worker 加集成测 `tests/ai-bridge.test.js`
时才暴露：SW 真跑一遍，才看见这条链路一直是死的）。

### 「等了 300 秒还没回来，可我 API 后台用量是 0」怎么查

"一直在等"这一句涵盖了三种完全不同的病，修法互不相干，所以界面把它们拆开。AI 那栏有个
**「测一下连接」**按钮：走的是与真请求同一条链路（同样候选顺序、同样头部、同样确认闸），
但正文是 `core/ai-endpoint.js` 里写死的 `ping` 一个词 —— 不含页面标签、不含槽位表、更不含你的资料。
15 秒内给结论，并附时间线（上行多少字节、多久收到响应头、多久收到正文）。

| 结论 | 意思 | 下一步 |
|---|---|---|
| 通了 | 网络和凭据都没问题 | 那"问 AI"干等就是模型生成慢：少问几栏、调大上限、或换非 reasoning 模型 |
| Key 被拒（401/403） | 请求到了对端、被挡在鉴权 | 被拒的调用一般**不进用量记录**，"用量为 0"与此一致：重录 Key |
| 没有聊天端点（404） | 路径没对上 | 看结论下列出的实际地址，Base URL 一般填到 `/v1` 为止 |
| 被限流（429）/ 对端报错（5xx） | 额度或对端的问题 | 等一会儿、换模型，或看服务商状态页 |
| 这台机器连不上该域名 | 连不带凭据的 GET 都不通 —— **请求根本没出门** | 查代理 / VPN / DNS / 防火墙（公司网络常拦境外 API 域）；用量必然是 0 |
| 域名通、POST 被拒 | 简单请求过得去、带 `authorization` 的 POST 过不去 | 多半是代理/防火墙只放行简单请求，或 CORS 预检没过；把这一行结果发给维护者 |
| 没有第一个字节 | 域名通、非流式沉默，**换成流式也摸不到第一个字节** | 对端确实没回话：查服务商状态页、账号是否被限 |
| 路通，只是在慢慢生成 | 非流式没吐字节，流式几十毫秒就摸到了 | 这是"慢"不是"不通"：调大「回答长度上限」、一次少问几栏、或换非 reasoning 模型 |
| 流挂住 | 响应头到了，正文没写完 | 同上，另可少问几栏 |
| 重定向被拦 | 地址会把请求搬到别处 | 把 Base URL 填成最终地址本身（我们禁跟跳转，否则 Key 会跟着跑） |

**用量为 0 并不等于"没发出去"**：401/403/404/429 这类被拒的调用，多数服务商都不记用量；
反过来，"连不上该域名"才是真的一个字节都没出门。所以先看上面这条结论，再决定查网络还是查 Key。

每次真调用也带时间线（"上行 X 字节 · 响应头 Y ms · 正文 Z ms"），失败时一并念出来 ——
没有这行，"网络不通"和"模型在慢慢想"在界面上长得一模一样。等待期间还有个**「取消等待」**：
它真的中止在飞的那次 fetch（不是只把界面字样清掉），报成"已取消"而不是"超时"，
也不会顺手再发下一个候选地址。判定逻辑是纯函数（`classifyPing`），
闸门与载荷在 `tests/ai-bridge.test.js` 里用真 service worker + 假 fetch 跑过：
没勾确认时自检一个字节都不发；那次对照 GET 不带任何头部（Key 绝不能跟着走）。

## 填真实信息之前：数据在哪、谁会出去

- **简历资料只在你本机**：`chrome.storage.local` 的 `profile` 键（浏览器自己的 profile 目录，
  不是云端同步 —— 扩展没有 `storage.sync` 权限）。它不会出现在任何下载物里：
  「下载空白模板」导出的是空模板，「生成诊断包」导出的是站点 DOM 元数据与映射表（脱敏视图）。
- **整个扩展只有一处会发网络请求**：service worker 里那个 AI 调用。
  另外两处 `fetch` 都是 `chrome.runtime.getURL(…)` 读扩展自己打包的 JSON。
  不配 Key、不点确认，就一个字节都不出门。
- **两条 AI 链路各守各的边界**：填写侧只发页面字段名（发送前 `assertNoProfileValues` 逐值自检，命中即拒发）；
  导入侧只发本地判不动的残段原文（逐字摘录、按次确认、号码样式整段拒发）。
- **Key**：默认只在 `chrome.storage.session`（重启即失效）；勾"记住"才进 `local` 的独立 `aiSecrets` 桶，
  那是明文落盘，代价与适用场景写在上面那节。Key 与 origin 绑定、禁跟跳转、界面不回显、不进 settings、不进导出。
- **界面注入**：`tests/xss.test.js` 把 `<img onerror=…>` 塞进简历取值、站点标签、回读值、缺口原因与 AI 回显，
  断言扩展页面里不出现可执行节点（同时原文不能被吞掉）。这条很重要：
  侧边栏是插件页面，能读整份简历，任何一个渲染点漏转义都等于开了一条外传通道。
- **权限面要如实说**：`host_permissions` 与 content script 是 `http/https *`，也就是说这个扩展
  *有能力*读任意站点的 DOM（它必须能在任意招聘网站工作）。代码层面它只在被消息驱动时才扫描，
  不驻留定时器、不自动读取。想要更严，可以把注入改成"只在你点图标的那个标签页按需注入"（`activeTab`），
  这是一项待办改动，现在的实现还没做。

## 保险箱：把资料加密到你选的本地文件

侧边栏「保险箱」一节：**口令 → PBKDF2-SHA256(600,000 轮) → AES-256-GCM**，整份 profile 变成一个
只有密文的 JSON 文件（`nw-vault-v1`）。写入优先用浏览器的文件选择器（`showSaveFilePicker`，
Edge/Chrome 支持），所以位置你定；不支持时自动退化成下载到浏览器下载目录，并在提示里说明。
读回来时先解密、再显示「补上 N 栏、改掉 M 栏、清空 K 栏 + 会被清空的栏名」，**你确认之后**才覆盖
浏览器里那份工作副本。

一句要说清的话：**换目录本身不等于更安全**。两处都在同一个 Windows 账户下，能读你磁盘的东西都能读它们，
而且都是明文；反过来，`文档`/`桌面` 经常是 OneDrive 的同步范围，把明文简历放过去比留在浏览器 profile 里
更容易外流。所以真正加了一道墙的是加密，不是路径。

也请把边界看全：

- **浏览器里那份工作副本仍是明文**（`chrome.storage.local`）。这是"扫描时不逼你输口令"换来的代价；
  要把这一层也加密，就得每次填写都解锁，本扩展没有默认这么做。
- **口令没有找回机制**：忘了就打不开，代码里不存在后门，也别指望以后加。
- 加密防的是"文件被别人拿走"（拷盘、误传网盘、电脑丢失）；**防不住**你正开着侧边栏时的截屏、
  键盘记录与读进程内存 —— 使用时资料必然在内存里是明文，这是所有本地方案的共同下限。
- 口令只在那一次操作里用一下：不写 `storage`、不进日志、不进任何发往后台的消息（有测试逐条钉住）；
  用完清空输入框，但 JS 无法真正清零内存里的字符串，所以公共电脑上别用。
- 保险箱文件里除密文外只有格式、算法参数与时间戳 —— **不含槽位名、不含分组、不含条数**，
  否则"这是一份简历、里面有证件号"这种事实本身就会泄露出来。

## 数据到底存在哪个文件

扩展没有服务器，也不申请 `storage.sync` —— 一切都在**浏览器自己的存储**（`chrome.storage.local`）里。
Windows 上它是浏览器 profile 下的一个 LevelDB 目录：

```
Chrome: %LOCALAPPDATA%\Google\Chrome\User Data\<配置文件>\Local Extension Settings\<扩展ID>\
Edge:   %LOCALAPPDATA%\Microsoft\Edge\User Data\<配置文件>\Local Extension Settings\<扩展ID>\
```

目录里的 `*.ldb` / `*.log` 就是数据本体。整个扩展只写三个键：

| 键 | 内容 | 什么时候存在 |
|---|---|---|
| `profile` | 你填的简历（含中英两份值） | 只要保存过就有 |
| `settings` | Base URL、模型名、等待与长度上限、三个授权开关、编辑语言 | 改过任何设置就有 |
| `aiSecrets` | **API Key 明文** | 只有勾了「记住 Key」；没勾时 Key 只在 `chrome.storage.session`，关掉浏览器就没了 |

几件必须知道的事：

- **明文，不加密**。扩展拿不到系统钥匙串（要走 DPAPI 就得装本地程序，那违反"纯浏览器插件"的边界），
  所以能读你这个 Windows 账户磁盘的人或进程都能取出简历内容。公用电脑别勾「记住 Key」。
- **解压加载的扩展 ID 由文件夹路径决定**：把仓库换到别的目录，ID 就变了，
  旧目录里的数据不会跟过去 —— 这就是"我资料怎么没了"的常见真因。ID 在 `edge://extensions` /
  `chrome://extensions` 的扩展卡片上能看到（需先打开开发者模式）。
  也可以自己算：`node tools/ext-id.mjs "C:\路径\nw-autofill"`（ID = 路径 UTF-16LE 的 SHA-256
  前 32 个十六进制位，逐位映射 `0→a … f→p`），它直接把那两个 `<扩展ID>` 目录对上号。
- **想看里面存了什么**，别去读 `.ldb`（二进制且可能被压缩）：在扩展卡片上点「Service Worker」
  打开 DevTools，Console 执行 `chrome.storage.local.get(null).then(console.table)`。
- **备份**用侧边栏的「导出资料 JSON」（明文，只含 `profile`，不含端点与 Key）或「保险箱」一节
  （**加密**，口令 → AES-256-GCM，见上一节）。下载/写文件之前都会先弹确认，因为里面是明文个人信息。
- **彻底清掉**：先「清除」删 Key、清空资料并保存，再移除扩展，然后删掉上面那个 `<扩展ID>` 目录。

## 开发

```bash
npm install            # 只装 jsdom，用于离线评测
npm test               # core/ 纯函数单测
npm run hit            # 在 test-forms/ 仿真表单上跑命中率判分
npm run check          # 两者一起
```

改了任何"用户重载扩展才会生效"的行为（core / dom / ui / background），把 `core/build.js` 里的
`BUILD` 末尾序号 +1：侧边栏顶栏与探针导出物都取这一个号，它是"你到底跑的是哪一版"的唯一答案。
`tests/extension.test.js` 会拦住任何在别处再写一个日期版本号的作法。

目录分层与依赖方向见 `UPSTREAM.md`；需求与验收标准见 `docs/REQUIREMENTS.md`。
