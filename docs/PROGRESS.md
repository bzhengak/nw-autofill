## 二、"技术上做完了、但证据没闭环"的四件

1. **真实站点覆盖率**：现在能说的是"11 份仿真表单 191 个期望全中、越界 0"，
   而仿真页是我们照记忆搭的。你在 tupu360/埃森哲那张上真实跑出来的数字才是产品指标（任务 #12 仍未结）。
2. **认选项（档 A/C）的实际收益**：装配层测证明链路是通的（请求不出取值、决定能落到 select 的码值），
   但"真页面上它到底认对几栏"要你的诊断包回证。
3. **两屏界面**：收纳是照你选的方案做的，但"要点的东西是不是真少了"只有你用一轮才知道。
4. **CI 已经真跑过一轮了（2026-10-05）**，而且正是这一轮把两个"本机看不见的问题"逼出来：
   `node --test tests/` 在 Linux 上被当成"把 tests 当一个测试文件跑"；测试里
   `globalThis.navigator = …` 在 Node 22 上抛 TypeError（Node 21+ 它是只读全局），一次连带 90 条红。
   两个都是"我这台机器全绿、别人的机器全红"那类 —— 记在这儿，是因为这类问题只会继续出现在
   我还没跑过的环境里（浏览器端 E2E 同理）。

   地址只写在 `git remote -v` 里，不抄进文档，免得这份记录本身变成身份线索），
   Actions 在 Node 20 与 Node 22 上各 8 步全绿。
   **version 定案：就停在 0.1.0**（我提过抬到 0.4.x，你否了 —— 商店与"我的扩展"页只看 version 这件事
   等你真要做分发时再说，别再提）。
   **身份信息已彻底清除（2026-10-05，两步）**：
   ① 先改写历史 —— 样例数据里的真人姓名、本人学校（中英文两种写法）、亲属名、真手机号、
      以及这份文档里出现过的账号名，连**提交信息**一起换掉；
   ② 再**删库重建** —— 因为改写只是让旧提交从分支上消失，GitHub 按旧 SHA 一度仍能取到。
   验法不是"看一眼最新文件"，而是扫**全部可达对象**（741 个 blob + 所有 commit/tree，残留 0），
   再从新仓库**全新克隆**装依赖跑一遍（569 条全绿），并确认旧 SHA 现在返回 "No commit found"。
   仓库 id 也换了（旧 → 新），fork 数 0、私有。
   **只剩一个尾巴**：改写前的完整历史备份在仓库外的 `nw-autofill-pre-rewrite.bundle`，
   **那个文件里仍然带着旧姓名与旧手机号** —— 新历史已验证无误，可以直接删掉它。
   **顺带被这次验证抓出来的一条真 bug**：全新克隆在 Windows 上按 `core.autocrlf=true` 检出成 CRLF，
   而 `tests/extension.test.js` 有一条按源码文本开固定宽度窗口的断言，行尾多一个 `\r` 就把要找的句子
   挤出窗口 → 别人拿到的代码是红的。已加 `.gitattributes`（`text=auto eol=lf`）钉住检出，
   并让测试读源码时自己归一行尾。**教训：验"能不能给别人用"要看全新克隆，不能只看自己的工作区。**

## 五、还没排期但值得记着的风险

- **明文存储**：`chrome.storage.local` 与保险箱文件都是本机明文（MV3 拿不到系统钥匙串，装 native host 违反"纯插件"边界）。
- **旧 service worker**：重载扩展后旧 worker 可能还在服务消息（面板新、后台旧）。构建号比对已经能看出来，但文档要教一句"关掉侧边栏再重开"。
- **词典是唯一护城河也是唯一债**：别名表越长，误伤面越大（今天裸词那三条判据就是为它补的）。
- **判分语料的自我强化**：11 份仿真页与词典出自同一双手，全绿不等于真站点对。
