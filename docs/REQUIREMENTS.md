## 0. 一句话目标

做一个 Chrome / Edge 通用的 MV3 扩展，在**公司自建网申页面**上把你简历里的客观信息一次性填对，填不出的明确标出来让你决定，**永不替你提交**。

覆盖范围（你已确认）：北森 / Moka / 大易 / 云用等 SaaS 招聘系统、互联网大厂自建系统、港企 SuccessFactors / Workday 级门户、银行与国企老式自建门户。**不含** LinkedIn、JobsDB 的自动化。

## 1. 底座选择（已核实，不是猜的）

**Fork：[1lck/AI-Resume-Form-Filling-Assistant](https://github.com/1lck/AI-Resume-Form-Filling-Assistant)**
上游 HEAD 固定为 `76c052d254da0b668ea1af9a1a2eb247dd3e62f8`（最后提交 2026-09-05）。许可证 **GPL-3.0**。

选它的理由（都是我去仓库里逐条核过的）：

| 事实 | 为什么关键 |
|---|---|
| 纯 MV3 扩展，`manifest.json` 在根目录，**没有构建步骤**，源码目录可直接 `加载已解压的扩展程序` | 你能立刻用上，不用先装一套 Node 工具链；改一行刷新即生效 |
| 架构是"AI 只做字段映射，写值由本地内容脚本确定性执行" | 与你要的混合模式完全同构，不用重构；也是可调试性的前提 |
| 已有 `node --test` 测试 + GitHub Actions CI（语法检查、扩展 JSON 校验） | 我要的"命中率可量化"有地方挂，不用从零搭测试骨架 |
| 已支持 input / textarea / select / radio group / checkbox group / contenteditable / 部分只读日期控件；有整页、增量、选区三种模式 | 省掉至少一周的底层控件适配 |
| 映射缓存按"页面结构签名"而非 URL | 同一网站改版后不会错误复用旧映射，这是长命的关键设计 |
| schema 已针对中文校招强化（培养方式、学号、导师、实验室、校园经历） | 中文侧起点高 |

明确继承它的两个短板并列为待办：**不支持 `<input type=file>` 上传**、**没有文件解析**（只吃粘贴文本 / 带文字层 PDF 的简陋导入）。

已排除的底座：
- [TshyGO/resume-form-assistant-plugin](https://github.com/TshyGO/resume-form-assistant-plugin)（MIT，今天仍在提交，中文适配最好）：架构是"插件 + Rust/Tauri 桌面端"，插件不存数据、AI 由桌面代发。fork 它等于必须替用户装一个桌面程序，与你"就一个浏览器插件"的要求冲突。它的**字段别名词典思路**和**填写诊断面板**值得借鉴。
- [OpenJobAutofill](https://github.com/Br1an67/OpenJobAutofill)（MIT）：AI 只见字段名不见取值的隐私边界设计很好，我把它作为混合模式的默认策略搬过来；但项目 4 个多月停更、无解析、测试缺失，不适合当底座。
- FormFilla：**闭源**（README 自称 Proprietary / Closed Source，仓库只是文档与发布页），不可作为底座；它的匈牙利算法全局最优映射思路我会独立实现（算法本身不受版权保护，但不参考其代码）。

**许可合规**：现在你自己用 + 私有仓库开发 = 不构成"分发"，GPL 义务未触发。将来公开或分享安装包 = 分发，届时必须：保持 GPL-3.0、保留上游 LICENSE 与版权行、在 `NOTICE` 里写明修改点与上游 commit、提供等价源码。这些我会在 P0 就把 `LICENSE`/`NOTICE`/`UPSTREAM.md` 三件套立好，避免以后翻旧账。

## 2. 目标与非目标

### 目标（G1–G8）
1. **G1 一次录入，处处复用**：一份标准 profile（中英文双份标签别名），多模板切换（如"算法岗""港企英文""国企政审向"）。
2. **G2 本地优先匹配**：词典 + 启发式打分先跑，零网络请求即可完成大部分字段。
3. **G3 混合 AI 兜底**：只对**卡住的字段**、且**经你点一下"用 AI 解决"**才发起请求；敏感字段值默认永不外发。
4. **G4 站点适配可积累**：域名→适配档案（adapter），你踩过的坑沉淀成 JSON，越用越准。
5. **G5 中英文字段都能认**：`姓名 / 手机 / 期望城市 / 到岗时间` 与 `Family name / Given name / Do you require sponsorship to work in Hong Kong? / Earliest available date`。
6. **G6 结果可核对**：绿（已填）/ 橙（待你处理）/ 红（我认为是错的）三态 + 逐字段回读 + 必填项缺口清单。
7. **G7 可量化、可回归**：内置一套模拟各家族控件的本地测试表单，命中率用数字汇报，不拿真实投递试错。
8. **G8 数据不出本机**（AI 请求除外，且受 G3 约束）。

### 非目标（明确不做，这是特性不是欠缺）
- ❌ 不自动提交、不点"最终投递"、不批量投递、不做"海投"。
- ❌ 不破解 / 绕过验证码、滑块、MFA、登录。遇到就停下让你手动过。
- ❌ 不代做在线测评、性格测试、笔试、逻辑题。
- ❌ 不写主观长文本（自我评价、Why us、英文 Cover letter）：默认标橙留空。可选"AI 起草给你看"，但**永不自动写入表单**。
- ❌ 不做岗位抓取、公司情报、投递状态跟踪（那是 ASu-skills 那类项目的活，别混在一起）。
- ❌ 不采集你的数据、不加统计/遥测/analytics。

## 3. 功能需求（关键细节，请重点看 3.5 / 3.7 两处否决点）

### 3.1 Profile 与导入
- 单一 profile JSON，字段带：`path`（如 `education[0].school`）、`zh_labels`、`en_labels`、`abbrev`、`type`、`sensitive` 标记、`updated_at`。
- 导入通道：① **Markdown 简历**（规则解析标题层级分段，零网络）；② **带文字层 PDF**（扩展内打包 pdf.js，本地抽文字，再把文字按分段规则结构化）；③ 手填；④ 从 JSON 备份导入。
- 扫描件 OCR：**v1 不做**（你未选择该格式）。
- 导出 JSON 备份，换机可用。

### 3.2 扫描（Scanner）
- 覆盖 `input / textarea / select / radio group / checkbox group / contenteditable / 日期类 / 级联选择`。
- **Shadow DOM 递归穿透**（open root；closed root 记为不可见并标橙）。
- **iframe**：`all_frames: true` 注入，同源可直接穿；跨域由各 frame 独立扫描后经 background 汇总（这是北森 / 部分银行门户的真实形态）。
- SPA 分页：检测"下一步/保存并继续"，不猜、不自动翻页，只在当前可见页填。
- 字段上下文提取：label / `aria-label` / `placeholder` / 邻近文本 / 所属区块标题 / `name` / `id` 分词，全部保留为打分信号。
- 条件字段：识别"选了『是』才展开"的结构，按 adapter 里声明的顺序先答驱动字段再重扫。

### 3.3 匹配（Matcher，两级）
1. **本地（默认，零网络）**：别名词典精确/别名命中 → 归一化模糊（简繁、大小写、全半角、去标点、缩写展开）→ 结构信号（`name=`/`id=` 里的英文语义）→ 类型约束（邮箱/手机/日期/枚举/长度/身份证）→ **一对一全局分配**（匈牙利算法，避免两个字段抢同一个 profile 键造成串行错位）。
2. **AI（按需）**：仅把「未命中字段的标签与上下文 + profile 的**键名**列表」发给模型，取值在本机按返回的键路径取。→ 这就是 G3 的实现方式，也是 OpenJobAutofill 的隐私边界。
   - 若你显式打开"允许发送取值"开关，才带上取值；证件号 / 手机号 / 家庭住址这类 `sensitive=true` 的字段**即使打开也默认排除**。
   - 支持任意 OpenAI 兼容接口，Key 只存本地；请求经 background service worker 代理，内容脚本拿不到 Key。
   - 发出去的 prompt 在诊断面板里可查看（你能看见它到底拿走了什么）。

### 3.4 写入（Filler）
- 走框架原生 setter（React `HTMLInputElement` value setter + 派发 `input/change/blur`；Vue v-model；受控组件回读校验），失败降级 `execCommand` 与逐字符事件。
- 下拉：优先按可见文本匹配 option，自定义下拉组件按 adapter 声明的"打开→列出→按文本点选"协议走。
- 日期：站点格式探测（`YYYY-MM-DD` / `YYYY/MM` / `MM/DD/YYYY` / `DD MMM YYYY` / 港企常见的三段式 picker），先填后回读，格式不符则重试并记入 adapter。
- 单选/多选组：按答案语义选，组内无匹配则整组标橙，不猜。
- **写后回读**：每个字段写入后读回实际值比对，不一致即标红（受控组件"看起来填了其实没进去"是网申最大的坑）。

### 3.5 附件上传 ⚠️ 需要你知情的不确定性
多数网申最后一步要求上传简历文件。扩展里可用的路子是 `DataTransfer` 合成 `File` 赋给 `input.files`——**这条路我还没实测**（部分站点监听真实用户手势、自定义上传组件会拒绝合成事件）。
计划：P2 开头花 20 分钟做一个 spike 实测；若成立，做成"默认关闭 + 每次上传前明确告知文件名与目标站点 + 你确认才动"；若不成立，降级为**自动定位到上传控件并高亮，提示你手选**，同时明确写进文档。
→ 我不想在这里给你一个没验证的"支持"承诺。

### 3.6 核对与闸门
- 三态标记（绿/橙/红）+ 侧边栏字段清单 + 必填缺口清单。
- 提交前 diff 预览：把"我填了什么、站点回读了什么"并排给你看；**提交按钮我碰都不碰**。
- 误填回滚：一键清空本次写入的字段（记录写入前原值）。

### 3.7 Adapter 导入的安全边界 ⚠️ 一个否决点
Adapter 是 JSON，将来要能分享/导入（社区化前提）。恶意 adapter 可以把你的简历值和字段映射悄悄发去远端。
计划：导入时**显示 diff**，schema 层面**禁止任何远程 URL、脚本、`fetch` 类字段**，只允许声明选择器与别名；来源非白名单时首次启用要显式确认。
→ 若你觉得"我自己用不需要这么绕"，可以在 P5 再做，我会在 P4 留接口。

### 3.8 可观测
- 每次填写产出结构化 report：扫描字段数、本地命中数、AI 辅助数、回读不一致数、失败原因分类（无标签 / 类型不符 / 自定义控件 / 跨域不可见 / 条件字段未展开）。
- 本地 dashboard 汇总"按域名的历史命中率"→ 直接告诉你哪家还得再喂词典，也把改进方向从"感觉"变成数字。
- 一键导出脱敏失败案例（保留结构、抹掉取值）用于提 issue 或社区共建。

## 4. 架构与分层（严格依赖方向，下层不得 import 上层 / chrome API）

```
nw-autofill/
├── core/            纯函数：profile schema、词典、归一化、打分、匈牙利分配、日期格式策略
│                    ← 无 DOM、无 chrome.*，全部 node --test 覆盖
├── dom/             scanner / field-text 提取 / filler 运行时 / shadow+iframe 遍历
├── adapters/        声明式 JSON：域名匹配、控件协议补丁、别名补丁、已知陷阱
├── ai/              映射请求构造、响应校验、敏感值过滤、prompt 可见性
├── ui/              side panel（主）+ options 简历编辑页 + 三态覆盖层高亮
├── background/      MV3 service worker：跨 frame 汇总、AI 代理、存储、report 落盘
├── parsers/         md 解析 + pdf.js 打包与文字抽取
├── test-forms/      本地仿真表单（见 §5）
└── e2e/             Playwright 加载扩展跑回归，输出命中率报告
```

技术栈：原生 JS（ESM）+ MV3，无框架、无打包器；pdf.js 与匈牙利算法实现**本地打包**（MV3 CSP 禁止远程代码）；E2E 用 Playwright Chromium `launchPersistentContext` + `--load-extension`。

UI 兼容：Chrome 114+ / Edge 114+ 用 Side Panel；更老版本降级为独立标签页 + popup，功能等价。

## 5. 验证方法（我认为这是整个项目最重要的一节）

真实投递不是测试环境。我会做一套**本地仿真表单**，把四类目标站点的控件形态复刻进去，回归跑在这套表单上：

| 测试页 | 仿真对象 | 考察点 |
|---|---|---|
| `plain-cn.html` | 银行/国企老式表单 | "贵姓""最高学历（含在读）""籍贯（精确到市）"这类歧义标签 |
| `element-ui-cn.html` | 北森 / 大易常见栈 | Element 自定义 select、级联 cascader、只读日期 picker |
| `antd-react.html` | 字节/腾讯/美团/阿里自建 | React 受控组件不认 `value=` 直赋、条件展开字段、radio 组 |
| `moka-multi-step.html` | Moka | 分页长表单、必填校验、附件步骤 |
| `sf-career-center-en.html` | 港企 SuccessFactors | 英文标签、Shadow DOM、`mm/yyyy`、大量 yes/no 合规题 |
| `workday-en.html` | Workday | 自定义日期控件、"Do you require sponsorship?"、地址三段 |
| `cross-frame.html` | iframe 嵌套 | 跨域 frame 汇总、部分 frame 不可见的降级 |

量化定义：**字段命中率 = 回读一致且值正确 / 可填字段总数**（分母不含验证码、测评、附件）。验收门槛见 §6。

真实站点验证只能由你来做（需要登录态和你的账号）：约定用**低意愿公司**当靶场——每家先在填完页面上核对，不点提交就退出。这样即使填错也不会污染真实投递记录。

## 7. 风险登记（不粉饰）

1. **命中率天花板**：中文老式门户标签歧义极大（"贵姓""是否独生子女"），纯规则会有一批字段永远只能标橙。这是问题本身决定的，不是工具差。混合 AI 是唯一出路，但受你隐私策略约束。
2. **站点改版**：大厂系统季度级改版，adapter 会腐化。缓解 = report 驱动 + 快速补丁 + 回读检测（填没填进去我立刻知道）。
3. **附件注入未验证**（§3.5）。
4. **风控**：纯扩展 + 人工提交，风险远低于自动提交脚本；但仍不建议在页面里高频机械点击，也不要在同一 IP 下短时间批量操作。
5. **单人项目**：fork 后不再依赖上游（上游 3 位贡献者、最后提交 09-05，本身更新很慢），全部维护落在你和我。
6. **跨域 iframe 的可见性**：部分平台把整段表单放进第三方域名的 iframe，扩展能注入但读不到对方 DOM 结构细节，命中率会明显掉一档。
7. **Edge 差异**：Side Panel 与部分 CDP 行为在 Edge 上有细微差异，P2 起双浏览器都要跑。

## 8. 需要你提供的东西

开工 P0 不需要任何输入，我直接建骨架。**P1 开始需要**：
