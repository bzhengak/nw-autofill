## 三个结构性发现（影响的不是一家站点）

### 1. Moka 把每段学历**平铺成具名字段**，而不是重复区块
Shopee 同一页里同时出现：`硕士毕业学校（本科无需填写）`、`本科毕业学校`、`高中毕业学校`、`本科GPA（实绩/总分）`、`本科专业排名`。
我的 profile 是 `education.N.*` 列表 → 必须有"标签里的学历层次 → 列表槽位"的映射规则，否则三段会互相抢同一个 `education.0.school`，而且抢错了**不会报错**。
→ 已落地（2026-09-26）：adapter 新增 `degreeSlotPins`（`{match, degree, subfield}`），按 profile 里 `education.N.degree` 的实际学历值定位槽位；资料里没有那一级学历 → 缺口 `degree_slot_unresolved`（橙色交人工），绝不拿"最像的那段"顶替。判定只用标签/name/id，不用 placeholder（"请输入本科学校"这类示例会把硕士栏串到本科槽）。同一标签同时提到两个学位时（`硕士毕业学校（本科无需填写）`），取学位名出现更早的那个。回归见 `test-forms/moka-flat-degree.html`。
>
> 顺带挖出一个更普遍的 bug：`itemIndex` 原来按"全页面第几个重复区块"编号，老式 `<fieldset>` 布局里 Personal/Education/Work 结构相似会被归成一组，教育经历于是带着 `itemIndex=1` 去对齐 profile，把硕士槽漂到本科槽（`sf-plain-en` 命中率当场从 100% 掉到 72%）。现在改为按"同一章节内第几块"编号。

### 2. AntD 系的"下拉"是一个 `div[role=combobox]` 配一个**匿名 input**
五矿 27 个、招行/拼多多 8 个 `div/combobox`，同时导出里出现大量 `(无)` 标签的 input 与"请选择×"标签成对出现。
危险在于：带 `id`/`name` 的那个匿名 input 会被当成独立字段并**被打字**，而下拉的真身是那个 div。
→ 方案：scanner 把 combobox 与其内部/紧邻 input 合并成一个字段（kind=combobox），命中我们既有的 `custom_control` 拒填规则，不再生成可写字段。

### 3. 招行的日期字段标签全是 `请选择时间`
真实标签（开始时间/结束时间/获奖时间…）在 DOM 里没被我们的标签策略抓到，退到了 placeholder。
这类"泛提示语当标签"会让我们把时间字段全部混在一起。
→ 方案：标签策略增加**候选文本打分回退**（社区同类项目 `shared/field-text.js` 的思路）：当首选标签是泛提示语时，在最近容器内收集短文本候选并按关键词/长度/标点打分重选。
同时"必填星号位置不固定"（`姓名*`、`*姓名*`、`毕业时间*?`、`最高学历*?`）要在归一化里剥干净，包括 SVG 噪声标签 `Created with Sketch.`。

## SuccessFactors / 汇丰两页"导出失败"的真实原因（已确认并修复）

用户第二次导出后拿到了两个 JSON，`controls: 0` 但结构合法：
- 一个 `url` 是 `match.adsrvr.org/track/cei?...`（广告交换的 cookie-sync 框）
- 一个 `url` 是 `apply.careers.hsbc.com/widgets/cookiemanageriframe/`（cookie 同意框）

**根因不是页面太重**，而是消息选路：`chrome.tabs.sendMessage(tabId, msg)` 不带 `frameId` 时会广播给该标签页全部 frame，
而 Promise 只取**第一个应答**。第三方框是几 KB 的空壳、`document_idle` 早就跑完，秒回；
真表单框要动态 `import()` 探针模块 + 扫全量 DOM，慢半拍 → 于是"导出"导出了广告框。
之前给它加的样式表上限是治错了方向（那个优化本身有价值，保留）。

**修法（两条，方向不同）**：
- 只读探针：遍历 `chrome.webNavigation.getAllFrames()` 的全部 frame，按 `控件数 + 是否第三方 junk URL + 是否顶层框`
  打分挑一个"最像真表单"的框返回，并把 `frameReport`（选了哪个框、每个框多少控件）一起带出去显示在侧边栏。
- 写入路径：反而**收紧成只发顶层框**（`{ frameId: 0 }`）。广播式写入意味着可能把资料打进第三方 iframe，
  这是不可接受的行为；表单确实在首方 iframe 里的站点，宁可明确不支持也不能误写。

教训沉淀：**任何"多框广播 + 取第一个应答"的实现都是竞态**，与页面轻重无关。

## SuccessFactors Portal 真实结构（2026-09-27，frame 选路修好后拿到的两份）

`career10.successfactors.com/portalcareer?company=johnswireP2`：frame#0 · 97 控件 · 39 可见 · 6 个跨源 iframe · 3 个 shadow host。
`career2.successfactors.eu/careers?company=hsbcholdin`：frame#0 · 179 控件 · 63 可见（**落在登录/注册面板**，不是简历表单——导出必须在填简历那一步做）。

家族级事实（不是某一家租户的措辞）：
1. **它的"下拉"是 `<input type=text role=combobox placeholder="No Selection">`**，语言切换甚至是 `<a role=combobox>`。
   原来 `kindOf()` 按标签名判：`input` 分支先 return 'text'，role 永远看不到 → 会往下拉里打字。
   现在 role 先于标签名，且计划阶段就归 `custom_control`（不是等 filler 失败再报红）。
2. 日期占位符就是 `DD/MM/YYYY`（en-GB），模板推断已覆盖；`labelVia=for` 是主力，`aria-label` 次之。
3. **`If other University/College, please specify` 是条件框**：上面那个下拉选了 Other 才填。
   把它当普通学校字段填 = 同一个值写两遍。租户级 skip 掉（`conditional_other`）。
4. 职位搜索区的 `Search by Keyword` / `Search by Location` 与简历字段同页 → 误填等于把城市名打进取框。

这四条换来三条打分层的通用修正（都在 `tests/core.test.js` 里有断言）：
- **显式 `<label for>` 不该被长度上限杀掉**：那条 42 字符的 SF 标签被丢弃后，上一节的 `<h3>Personal Information</h3>` 冒充了它的标签。显式来源的上限放宽到 90。
- **英文右分支**：`Current Job Title` 问的是 title，`current job` 只是修饰词；别名不含标签中心词时降权，否则"是否在职"会赢过"职位名称"。
- **精确别名能扛住错的章节线索，扛不住列表槽位**：SF 把 Expected Salary 放在 Employment 小节里（章节线索是错的），字面命中该保住；但「政治面貌」在基本信息里时，`family.0.political` 同样是字面命中，却因为是可重复槽位必须让位。

## 判分器自己也要有回归（一次假警报换来的）

`mustNotTouch` 原来用 `el.value` 判"有没有被写过"，而 **checkbox 的 `value` 天生是 `"on"`** →
所有 cookie 开关都被误判成越界。假警报比漏报更危险：它会让整套门槛失去意义。
现在按控件类型分开判（checkbox/radio 看 `checked`，select 看 `selectedIndex`，button/submit 永不判）。

## Klook（Moka）实测跑通后暴露的未解问题（2026-09-27）

用户第一次在真实页面扫描，结构层没问题（`本页适配器：moka`、只读/下拉/成对日期都正确拒填），
但暴露一个我们**还没解决**的问题，写下来而不是掩盖：

Moka 的重复经历区块里，每个字段各自一个 `.mk-form-item`，页面**没有小节标题、也没有可识别的卡片包裹**。
于是 `公司名称 → internship.0.company` 与同块的 `职位名称 → work.0.title` 可能来自 profile 的不同条目：
两个路径各自都合法，匈牙利也就不会拦，但落到页面上就是"把 A 公司的职位写成 B 公司的职位"。

- 现在 `tools/expected/moka-kpmg-en.json` / `moka-klook-cn.json` 对这类字段只允许 `oneOf` 一组合理路径，
  **判分不承认配对正确**，避免把没解决的问题写成"通过"。
- 真正的修法要等 P4：一致性断言（同块内的字段必须来自同一个 profile 列表条目），
  实现点是把 `detectRepeatedBlocks` 的卡片边界判定从"结构签名"扩到"重复标签序列 + 缩进/包裹猜测"。

## 2026-09-28 · 年 + 月 成对框：从"整组拒填"改成"一个日期、两笔写入"

实测形态（四份判分表单、14 个框）：Moka 把 `年/月` 两个 `<input placeholder="年|月">` 塞在同一个
`.mk-control` 里，Workday 用「自:」「至:」两个 `wd-field`，海康自建用 `.se-field`。以前整组标
`composite_date` 交回人工，理由是"单个框装不下一个完整日期，两个框会各自去抢 profile 的日期列"。
这个理由成立，但结论过头了：抢列的问题在于**规划粒度**，不在于控件不可写。

改法（三段，缺一都会留下假绿）：

1. **扫描阶段配对**（`dom/scanner.js` `markCompositeDatePairs`）：同容器 + 同标签的年框与月框按
   文档顺序两两成组，给出 `datePair = { id, part, role, roleSource }`。落单的年框仍然带
   `compositeDate` 标记，否则它会被当成普通文本框，把整个日期写进年份框。
2. **一组 = 一个问题**（`core/matcher.js`）：组长（年框）单独成行进匈牙利矩阵，只占一个 profile 列；
   落笔前在 `assignments` 末尾统一展开成每成员一笔，`dateFormat` 分别给 `yyyy` / `MM`。
   展开必须放在最后而不是打分分支里：Moka 适配器一钉位，只钉年框就会把月框整个弄丢（实测踩过，
   `tests/core.test.js` 有一条专门盯它）。
3. **起止角色**：标签自己说了「自/至/开始/结束」→ `roleSource='label'`；只写了「起止时间」这种
   一句问两个框的范围词 → 按出现顺序推（第一组是起），`roleSource='order'` 一律黄字，
   并且**保留先前的黄字理由再追加**，不让两处说明互相覆盖。

顺带修掉一个真 bug：`detectRepeatedBlocks` 会把「自」「至」两个纯日期行当成第 0/1 段经历，于是
`自 → work.0.startDate`、`至 → work.1.endDate` —— 一个时间段被拆到两段经历上，而且"自"那侧还能拿绿字。
现在纯日期壳子不参与重复编号（`isDatePartShell`）。

仍未解决（判分标准里如实写着，不掩盖）：Moka 的起止行**没有小节标题**，落在哪一段经历说不清，
`y1..m2` 目前会拿到 `education.0.*` 这类同样合法但可能错位的路径，所以必须一直是黄字。
根因是 `sectionHint` 只来自容器标题；下一步是让日期行继承邻近字段的章节线索（见任务 #5 一致性断言）。

## 2026-09-28 · 第二轮：三个"看起来是我们的词不够"其实不是的归因错误

跑完拆日期后把剩余缺口按原因排了一遍（`custom_control=27`、`no_candidate=12`、`subjective=5`…），
逐条查下来发现 12 个 `no_candidate` 里有一多半是**我们自己的判读错误**，不是资料缺词：

1. **附件按标签拒 → 漏进来被报成"没词"**。`BLOCK_PATTERNS` 的 file 规则要求标签命中
   「上传/附件/upload/attachment」，于是 Sea 的 `Resume`/`Transcript`、Workday 的「简历履历」漏网，
   落到候选打分后变成 `no_candidate`。用户看到"没有这个词"会去补资料，而真相是"这栏得你自己传"。
   现在 `kind === 'file'` 直接归因 `file`，不再看标签。
2. **枚举选项比对一直拿到 `[object object]`**。`scorePair` 里
   `pageField.options.some(o => profileField.options.some(p => normalize(o) === normalize(p)))`
   的 `o` 是 `{text,value}` 对象，`normalize(o)` 恒等于 `"[object object]"` → 永远 0 命中 →
   **所有带选项的枚举字段都在吃 ×0.8 惩罚**。后果不是"少点分"而是排错序：SF 的
   `Current Work Authorization` 输给"工作城市"（0.529 vs 0.554），整栏红字。改成比 `text/value`
   并允许包含关系后，它自己回到了 `hkGlobal.workAuth` 并选中 Hong Kong Permanent Resident。
3. **裸 `work` 把合规块认成工作经历**。SF 的 `<legend>Work Authorization</legend>` 命中章节词 `work`
   → 该块字段拿到 `sectionHint=work` + 区块序号 0 →「Do you require sponsorship…」对
   `hkGlobal.needSponsorship`（别名精确包含）被章节惩罚 ×0.75、槽位惩罚 ×0.8，0.84 掉到 0.50 出局。
   `work` 现在带否定前后词（authorization/permit/visa/status/…），`Work Experience` 仍然照认。

修 2 时顺带暴露并修掉一个更普遍的结构缺陷：**标签证据能撞到 1.0，结尾的 `Math.min(1, best)`
就把后面的槽位惩罚一起抹平**。精确命中的 `education.0.school` 与 `education.1.school`
都变成 1.000，匈牙利只能按列顺序随便挑 —— legacy 表单的「最高学历」因此拿到 `education.1.degree`
（本科）而正确答案是 `education.0`（硕士），而且是**绿字**。现在标签证据封顶 0.95，
章节/槽位的奖惩才有可见的地方。

同轮修掉两处"假红"（写入层）：`<option value="2">共青团员</option>` 这种码值下拉，回读拿可见文本
比码值永远不等 → 明明选对却报红；单选按 `value="M"` 勾上、验收却比 `男` → 同样假红。
现在写入与回读共用同一个 `hitOf` 判定；站点真的把选择改回去时报 `selection_reverted` 红字（保留），
计划阶段就知道选项对不上的（`needsChoice`）报橙色"需人工"而不是红色"填错了"。

结果：9 份判分表单 186/186、越界 0、**红字 0**（本轮开始前是 7 条红字），
`no_candidate` 从 12 降到 2（Workday 的「区」「电话分机」——profile 里确实没有这两栏，属真缺口）。

## 2026-09-28 · 摊平表单的记录配对：出现次数是能用的证据，但不是"哪段经历"的证据

`moka-klook-cn.html` 把两条工作经历摊成 8 个"一行一个控件"的 `.mk-item`，没有小节标题、没有卡片包裹，
`detectRepeatedBlocks` 找不到任何边界（每个容器只有 1 个控件）。同块的 公司名称 / 职位名称 / 工作职责
因此各自去抢 profile 列，会出现"A 公司的职位写进 B 公司那一栏"，而每个字段单独回读都是绿的。

试过、被否掉的做法：把 `sectionHint` 从邻近字段继承过来 —— **Klook 整份表单一个章节线索都没有**，
继承无源可继；有线索的表单（kpmg / workday）本来就已经对齐了。所以这条不在本轮做。

实际做法（`markRecordOccurrences`）：把"同一个标签第 k 次出现"当作"第 k 条记录"的证据。
三个关键约束，每一条都是实测踩出来的：

1. **只给确实重复的标签编号**（出现次数 ≥2）。一次性字段（学校 / 专业 / 姓名）没有"第几条"可言，
   给它们编 0 反而是无中生有 —— 老式 fieldset 布局的三个不同章节会被一起编号，
   硕士槽位漂到本科槽位（`tests/scanner.test.js` 有一条专门钉这个）。
2. **同一容器里的年月对折成一个单位**。Klook 的「起止时间」四个框 = 一条记录的开始与结束，
   按框计数会把它当成两次出现。
3. **`role=combobox` / `listbox` / `file` 不参与计数**。Sea 的 `Contact Number *` 是一个
   `div[role=combobox]` 壳子和一个真空输入框共用同一条 `aria-labelledby`，壳子占掉"第 1 次出现"之后，
   真输入框就成了"第 2 次"，实测去抢了 `family.1.phone`。

序号一律带 `itemIndexSource='occurrence'`，匹配器据此**拒绝开绿字**：它说得出"第几条"，
说不出"是工作还是实习"。绿字只认两种证据 —— DOM 区块序号，或页面小标题的章节归属与 profile 分组一致。
另外加了一条错位点名：第 k 次出现的标签如果被派到序号 ≠ k 的条目上，黄字说明会写
"这一栏是页面上第 k+1 次出现的「工作职责」，却拿到了资料里第 1 条，配对可能错位"。

效果：Klook 第 2 条经历的 公司名称 / 职位名称 现在都落在 `work.1.*`（以前一个 work.0 一个 internship.0），
剩下 1 处错位（`工作职责 → work.0`）被点名而不是静默通过。
判分 186/186、越界 0、红字 0、需人工 2；112 单测全绿（本轮新增 4 条，其中 3 条验证过"去掉实现就失败"）。

## 2026-09-30 · 「调用失败：http_404 Not Found」：错误正文的形状就已经指到了病根

用户实测 AI 兜底报 `http_404`，正文只有一行 `Not Found`。这一行本身就是证据：

- OpenAI 兼容层报"模型不存在/Key 不对"回的是 **JSON**（`{"error":{"message":…}}`）；
- 纯文本 `Not Found` 是**网关/静态路由**的 404 —— 说明请求根本没打到 API 路由上，
  也就是我们 POST 的那个 URL 路径不对，而不是模型名或 Key 的问题。

病根在老写法 `normalizeBaseUrl(base).url + '/chat/completions'`：大家嘴里的"Base URL"形状不统一，
两种常见粘贴必坏 —— ① 粘了完整端点 `…/v1/chat/completions` → 拼成 `…/chat/completions/chat/completions`；
② 只粘主机名 `https://api.x.test` → 少了 `/v1` 那一段。

改成 `chatEndpointCandidates()`（`core/ai-security.js`，纯函数）把粘贴形状收敛成**最多两个同源候选**，
出网那段整体挪进 `core/ai-endpoint.js` —— 留在 service worker 里就只能靠人在浏览器里试，
挪出来就能用假 fetch 离线测（`tests/ai-endpoint.test.js`，现 18 条）。

三条边界是这次一并钉死的：

1. **只有 404/405 才顺延下一个候选**。401/403/429/5xx/超时都只发一次：
   非路径错误重发等于多敲一次 Key、多烧一次额度、多等一遍时间（超时最狠，180 秒 × 2）。
   等待预算改成"整个调用共享一个 deadline"，不是每次各自 180 秒。
2. **候选永远同域**：Base URL 里塞 `//evil.test`、`@evil.test` 只会变成路径的一部分。
   代码里那行 origin 检查今天是**跑不到的后盾**（候选都由 `${origin}${pathname}` 拼出来），
   所以测试钉的是"所有候选同域"这个**性质**，而不是那行代码 —— 这行删掉测试不会变红，
   但如果将来谁把候选改成直接吃原文，性质测试就会红，后盾再兜住它。
3. **错误里必须带上下文**：404 会把**真正请求过的每个地址**逐行列出，「预览」也显示完整 URL 而不是 Base URL。
   两条 AI 链路（填写兜底 / 辅助导入）共用一份 `aiErrorText()`，两边都补了回归 ——
   只补一边是这类修复最常见的漂移方向。

顺手清掉两处"说了但没做"：`AI_ERROR_ZH.timeout` 还写着"（20s）"（上限早就能配了）；
详情区把上游原文拼了两遍（`aiErrorText` 已经带 detail，渲染点又加了一次）。

## 2026-09-30（再续）· 「等了 300 秒没结果，可后台用量是 0」——把"在等"拆成五种病

用户第二次报 AI 不可用时给了一条关键旁证：**API 后台没有用量记录**。这句话本身推不出结论，
因为至少五种情况都会长成"我一直在等"：

| 真相 | 会不会留用量记录 | 插件看到的现象 |
|---|---|---|
| 域名在这台机器上根本连不通（代理/VPN/DNS/防火墙） | 不会 | 干等到上限 |
| 域名通、带 `authorization` 的 POST 被中间设备拒 | 不会 | fetch 直接 reject，浏览器一律给 `TypeError: Failed to fetch` |
| Key/权限被拒（401/403） | 多数服务商**不记** | 有状态码 |
| 路径不对（404） | 不记 | 有状态码 + 一行 Not Found |
| 连上了、模型在慢慢生成（reasoning 尤其明显） | 答完才记 | 干等到上限 |

前两种"没出门"和后三种"出门了"的修法完全无关，而界面上它们是同一句转圈。
所以这一轮加的不是"再延长一点超时"，而是**观测**：

1. **时间线**：每次调用记 `上行字节 / 收到响应头耗时 / 收到正文耗时 / 是否中止`。
   `headersMs === null`（对方连话都没开始说）和 `headersMs` 有值但 `bodyMs === null`
   （说了一半卡住）是两件不同的事。失败时这行直接进状态栏，不用用户猜。
2. **「测一下连接」**（`pingAiEndpoint`）：与真请求同一条 `callChatEndpoint`
   （同样候选、同样头部、同样确认闸），只是正文换成 `core/ai-endpoint.js` 里写死的 `'ping'`。
   只有"一个 HTTP 状态都没拿到"时，才补一次**不带任何头部与凭据的 GET** 打同一 origin 的根路径 ——
   它就是为了让"域名连不上"和"域名通但 POST 被拦"分家。带 Key 的自检必须过同一道确认闸，
   这条在 `tests/ai-bridge.test.js` 里用真 SW 跑过（没勾确认 → 0 次网络调用）。
3. **判定表是纯函数** `classifyPing`：一开始我把判定写在计时器与 abort 的流程里，测试就得靠真等待，
   慢、脆、而且一红分不清是判定错还是计时错。抽成纯函数后每种输入各钉一行，跑完不到 1 毫秒。
4. **「取消等待」不再谎报成超时**：外部 `AbortController` 一路传到 `oneCall`，
   中止报 `cancelled`（且不再发下一个候选），与 `timeout` 分开。
   顺手补一个反例测试：假 fetch 必须像真 fetch 那样"信号一到就 reject"，
   否则测的是我自己的桩而不是中止行为 —— 第一版就是这么写出一个 180 秒不失败的挂死用例的。

一处诚实记录：**这次仍然没有证明用户那侧到底是哪一种**。上面五种可能性里，
只有跑到他机器上的「测一下连接」能把它塌缩成一句结论；我这边能做的就是把那五种分开显示，
而不是再猜一遍然后改一轮参数。

## 2026-09-30（第三）· 「自检回了个没见过的结果：unknown_message」——不是判定表漏了一格，是后台压根没这条消息

用户重载后点「测一下连接」，界面回的是兜底那句 `{"error":"unknown_message"}`。
这条错误的价值在于它**只有一个产地**：`grep -rn unknown_message` 全仓库只命中 service worker 的
最后那个 `else` —— 也就是说回话的那个 worker **没有 `nw:aiPing` 这个分支**，
而面板显然是新的（否则没有自检按钮）。结论：MV3 重载之后旧 worker 还在服务消息。

这不是理论风险：侧边栏与扩展之间挂着连接时，旧 service worker 可以被留着继续处理消息，
于是用户看到的是"我明明重载了，怎么还是老样子"。而这类误判的代价很高 ——
我们会把它当成行为 bug 去改代码，实际改的东西根本没跑起来。

修法不是教用户怎么重载（那还是会忘），而是**让界面自己报不一致**：

- `core/build.js` 里一个 `BUILD = '日期-序号'`，探针导出物的 `probeBuild`、SW 的 `nw:getState`
  与兜底回包、侧边栏顶栏全部取这一个来源；
- 面板每次 `refresh()` 比对 `state.build !== BUILD` → 顶栏直接显示
  「后台没跟上：去 chrome://extensions 把本扩展关掉再打开，然后重开侧边栏」，
  并把修法写在**文字里而不是 title 里**（侧边栏那么窄，悬停提示等于没有）；
- 自检遇到 `unknown_message` 不再走"没见过的结果"兜底，而是直接说这是旧后台；
- `tests/extension.test.js` 加了一条静态断言：别的层不许再自己写一个日期版本号 ——
  两处各写一个号，就又会回到"靠对话猜版本"的状态。

顺带一条与前两轮同源的教训：**用户报的症状要先排除"他跑的不是这份代码"**。
探针早就自带 `probeBuild` 了，但那条信息只在导出 JSON 里，界面上看不见，
所以这三轮里我们至少有一次是在给一个没生效的构建排查问题。

## 2026-09-30（第四）· 自检的第一版把自己骗了：拿 2000 token 的预算去测"通不通"

用户按指引重载后点「测一下连接」，回的是：

> 域名连得上，但 15 秒内一个响应字节都没回来（GET 却用了 43ms 就通）。
> 请求地址：`https://api.siliconflow.cn/v1/chat/completions`

这行数据本身很清楚：**路径是通的**（GET 43ms），端点形状也对（不是 404），
沉默 15 秒的是那一发 POST。而第一版自检的正文是写死的 `ping`，
**长度上限却沿用了真请求的 `max_tokens: 2000`** —— 对 reasoning 模型（SiliconFlow 上 R1 / QwQ /
Qwen3 思考模式都很常用）来说，思考链也算在答案里，15 秒内没生成完是正常现象。
于是自检把"对端在慢慢想"报成了"请求出门了、对端没回话"，结论方向整个反了。

三处改掉的不是措辞，是探测的物理形状：

1. **自检那一发 `max_tokens: 1`**。测的是"通不通"，不该给模型留思考的余地 ——
   一个词的请求还不回状态，才是路径/网络的问题。
2. **沉默时再补一发流式**（`stream:true` + 1 token，只摸第一个字节就撤）。
   非流式响应有个物理事实：**整段生成完成前服务端一个字节都不发**，
   所以"15 秒没字节"单凭第 1 发分不清"慢"和"不通"，必须靠流式那一发分开：
   摸到了 → `holding_response`（路通，是慢）；摸不到 → `no_first_byte`（真的没回话）。
   两个判定在 `classifyPing` 里是两行，测试各钉一条，并用假流（`getReader` 返回一段字节）验证。
3. **「回答长度上限」变成可配项**（`settings.aiMaxOutput` → 请求里的 `max_tokens`，默认 4000）。
   老实现写死 2000，几十个缺口的 JSON 回答 + 思考链本来就不够 —— 用户之前报的
   "AI 空输出"与这个形状一致（`reasoning_only` / `truncated`）。
   设置键叫 `aiMaxOutput` 而不是 `aiMaxTokens`：`sanitizeSettings` 有一条按**键名**拦秘密的闸
   （带 key/token/secret 的一律拒收，因为 settings 会被导出 JSON 带走），
   带 token 的键名会被它误杀 —— 这条不是绕开闸，是这条 `SETTING_KEYS` 断言先把坑照出来了。

对照探测（不带凭据的 GET）仍只在"一个 HTTP 状态都没拿到"时做一次；
被直接拒掉的 POST（`fetch_failed`）**不**再补流式探测 —— 那是"被拦"，不是"沉默"，
多发一发只会浪费一次额度并把判定搞混。这条也钉在测试里。

## 2026-09-30（第五）· 同一个地址：非流式 15 秒零字节，流式立刻开始回话 → 真请求改默认流式

用户按新自检跑出的结论是：

> 路是通的：非流式那一发在 15 秒内没吐字节，但改成流式后 0ms 就收到了第一个字节。
> 请求地址 `https://api.siliconflow.cn/v1/chat/completions`

两个收获，一个是我自己的错，一个是行为该改了。

**"0ms" 是我算错了基线**：`peekFirstChunk` 的计时从**响应头到达之后**才开始，于是任何流式响应都会
报成"0ms 就回话"，听起来漂亮、实际什么都没区分。现在统一从**请求发出那一刻**算
（`peekFirstChunk(res, ctrl, t0)` / `readSse(..., startedAt)`），这个数才有意义。

**真正的事实是**：同一个端点、同一个 Key，非流式 15 秒一个字节不发，流式立刻开始回。
这不是插件的毛病，是**非流式响应的物理形状**：服务端要等整段答案生成完才开始发。
那就没有任何理由让真请求继续用非流式去猜"它是在想还是没听见"。于是：

- 真请求默认 `stream: true`（`settings.aiStream`，可关）。SSE 帧按
  `choices[0].delta.content / reasoning_content` 拼回完整正文后，交给**同一个** `interpretAiReply` ——
  空正文 / 只有思考 / 被截断这些结论不能因为换了收法而分叉。
- 换来三件以前看不见的事：第一个字节什么时候到；超时或取消时**已经收到多少字**
  （"一个字都没回"与"回了一半卡住"是两种病）；以及流式中途断开时那半截长度。
- **自动退回**：只有"这条响应方式本身不被接受"（400/422、拿不到 body 流、SSE 读不动、
  200 但正文不是响应）才退回普通收法再试一次。401/403/404/429/5xx 与超时**都不退** ——
  换收法解决不了鉴权和限流，多发一发只是浪费额度、把等待时间翻倍。
  退回成功也在结果那一行说明"这次是换了收法才通的"，不让下一次继续踩。
- 假上游从此**两种形状都要有**：`ai-bridge.test.js` 里的 `okJson` 以前只给 `json()`，
  后台默认改流式后立刻红了 —— 它测的是一条现实中不存在的分支。真实 OpenAI 兼容端点在
  `stream:true` 下回的是 SSE，桩就得回 SSE。

顺带把"关流式"的代价写在面板上：关掉之后"慢"和"不通"重新变得同形，超时也更常见。

## 2026-09-30（第六）· 用户"看不到那个勾选框"：功能在，位置是错的

AI 通了之后第一句反馈是「看不到允许填入敏感字段的勾选框」。三个授权开关确实都在，
但它们住在 `#editor` 里，而 `#editor { display:none }` —— 要先点「编辑 / 导入 JSON」才存在。
更糟的是敏感字段那条提示写着"**在下方**勾选"，而"下方"那片是折叠的 JSON 编辑器：
一句话把人指到一个空位子上。

这不是文案问题，是**归类问题**：这三条勾管的是"要不要改敏感内容 / 要不要动页面控件 /
要不要降级填中文"，跟编辑 JSON 没有半点关系。现在它们有自己的一节「填写授权（默认全部关着）」，

顺手补了两个同类位置问题：

- 「导出资料 JSON」以前根本不存在，而**导出按钮如果放在折叠区里就等于没有**（测试里加了一条
  `closest('#editor') === null`，连"数据在哪"那段一起钉住 —— 折叠区里的说明文字等于没写）。
- 「这些数据到底存在哪个文件」从聊天里的口头解释变成面板里的常驻一节：Chrome/Edge 两条路径、

## 2026-10-01 · "存浏览器是不是不安全"：答案是换目录没用，加密才有用

用户看完上一轮的文件位置之后提了新要求：想改成存本地文件。先把威胁模型说清，因为它和直觉相反：

- 浏览器 profile 里那份和"随便一个本地文件"**在同一个信任域里** —— 同一个 Windows 账户下能读磁盘的
  进程/人都能读，两边都是明文。换目录不提供机密性。
- 更糟的方向是真实存在的：`文档`/`桌面` 常在 OneDrive 同步范围内，而 `AppData` 默认不在。
  也就是说"把资料从浏览器里挪出来"很可能等于"把资料交给云"。
- 所以真正的增益只有两个：**加密**，或者放到你自己控制的加密盘/非同步目录。用户选了加密 + 位置自选。

实现上的取舍（都写进代码注释与 README 了）：

1. 只用浏览器自带的 WebCrypto（PBKDF2-SHA256 600,000 轮 → AES-256-GCM）。不装本地程序、不接
   native host，因此**拿不到系统钥匙串**：口令每次手输，绝不进 `storage`、不进日志、不进任何回包。
2. 保险箱信封里除了密文只放格式、算法参数和时间戳。**连槽位数量、分组名都不写** ——
   那些足以让文件从"一团密文"变成"这是一份含证件号的简历"。测试直接钉字段清单。
3. **工作副本仍是明文**（`chrome.storage.local`），否则每次扫描都要输口令。这条没藏着：
   面板、README、代码注释三处都写，并说明想连这层一起加密要付什么代价。
4. 载入流程是"先解密 → 显示差异（补上 N、改掉 M、清空 K + 会被清空的栏名）→ 确认 → 才覆盖"。
   口令错或文件被改过一个字节 → GCM 认证失败 → **一个字节都不动**；这三条路径各有断言。
5. Node 20 与 Chromium 对 `deriveKey` 的参数个数要求不一致（5 vs 3）：先按标准三参调用，
   只在报 `arguments required` 时才用五参重试。写死任何一种都会在另一半环境里炸。
6. 文件写入优先 `showSaveFilePicker`（能挑非同步目录），没有就退回下载目录并**在提示里说明落在了哪**，
   同时提醒网盘范围。读取用 `<input type=file>`，不假装能后台监视文件。

**没有后门**：口令忘了就打不开。这句话在代码注释、面板与 README 里各出现一次 —— 一个"能找回口令"的
功能设计，等价于给所有拿到文件的人留了同一把钥匙。

## 2026-10-01 · 「下载下来的 JSON 里 en 是 {}」：界面有框、文件没坑

用户把空白模板下载下来想手写英文，发现 `"en": {}` —— 一个键都没有。这不是显示 bug，是我们把
英文值设计成**稀疏子树**（只在真填了的时候才有键）的必然结果：编辑器按 537 个槽位渲染输入框，
所以界面上切到 English 什么都有；JSON 里却只有一个空对象，手写的人不知道该写在哪。

改法与取舍：

1. `enSkeleton()` 从 `buildFields()` 推出一副完整骨架（**317** 个需要英文写法的栏位，空串落点），
   结构镜像中文侧；列表项预先补足长度，否则 `arr[2]=…` 那种跳着写会序列化成 `[null,null,…]`。
2. 骨架**只覆盖需要另一种文字的栏位**：日期/数字/邮箱/下拉这些两语同值的（210 个）不摆空框 ——
   一排永远用不到的空框和 `en: {}` 一样误导，只是误导方向相反。
3. 三处出门的地方都要带上它：模板下载、资料导出、面板里的 JSON 编辑框；再在
   `nw:saveProfile` 落库前 `ensureEnSkeleton()` 一次，老资料从此补齐。合并只补空缺，
   **已有英文值与 schema 之外的键一律不动**（这条有专门断言）。
4. 顺手抓到真 bug：`*En` 结尾的栏位（学校英文名、英文姓名、英文地址，共 10 个）取值本身就是英文，
   以前却被要求"再写一份英文的英文"，英文表单去读那个空壳 → **已经填好的英文名被当成缺英文留空**。
   现在 `isLangNeutral` 认 `En$`，骨架里不再出现 `en.education.0.schoolEn`，英文页直接读原值。
5. 空串不能污染判分：`countFilled`、`englishCoverage`、`lacksEnglishValue`、保险箱差异比对

6. 保险箱载入前的差异比对以前**只算中文路径**：一份"英文写法多一半"的保险箱会被报成"完全一致"。
   现在把 `en.` 路径一起送进比对，栏名前加「英文·」。

## 2026-10-01 · 第一次真实浏览器实测（途普 tupu360 / 埃森哲页）：三件事同时暴露

用户终于把扩展装进 Edge 跑了真实网申页（`careersite.tupu360.com/accentureats/resume/applicationView`），
一次报回来两个现象，加上我们自查出来的第三个 —— 三个都不是"模型慢"这类环境问题：

1. **「问 AI」被自己的取值自检拦死**：报 `internship[0].durationMonths（开头「12」）`。
   `assertNoProfileValues` 的判据是"资料里任何长度 ≥2 的值出现在待发文本里就算泄漏"，
   而待发文本里有页面自己的标签/选项/邻近文字 —— 资料填了 '12'、'2021-09'、GPA '3.8'、国籍 'China'
   就必然撞字。真实资料一进来这条闸就变成"永远拒绝"，等于 AI 兜底不存在。
   现在放行两类不构成身份的重合：**短数字与日期形状**（≤8 位：时长、年份、GPA、身高），
   以及**整串就等于页面自带词**的值（下拉里本来就写着 `China`）；判据在 `core/ai.js` 的
   `isIdentifyingValue` + `pageTokens`。手机号 11 位、证件号 18 位、姓名（含两个字的）照旧拦。
   `pageTokens` 只在"整串相等"时用，不做子串匹配 —— 真泄漏通常是把值拼进了更长的句子。
   两条新断言里有一条跑在**真 service worker** 上（`tests/ai-bridge.test.js`），因为这类"函数都对、
   链路是死的"的问题只有装配层能照出来。
2. **17 栏全是「(未命名字段)」**：这一页 41 个控件有 26 个拿不到标签。对照真实导出很干脆 ——
   同一行里的 `<input>` 在 form 内部就用 prev 兄弟拿到了 `*Name`，而 `<div role=combobox>` 的
   chain 顶到 `span.field-value field-editor` 就没词了：**途普给每个字段单独套一层小 `<form>`，
   标签写在这个 form 外面**（`span.field-label` 一类裸文本，里面不套 `<label>`）。
   老规则一条"遇到 FORM 就 break"、一条"标签分支里必须再有个 label/title 节点"，正好双双失效。
   现在补两条窄规则：① 从 form 往上**最多两层**，只收"不含控件、不是字段壳子、≤24 字、不是块级标题"
   的旁支；② 两列条目里，旁支自身类名像标签（label/title/caption/name/question/field-）且文本 ≤24 字也算。
   `test-forms/tupu-antd-cn.html` 里补了这段真实形状（2026-09-29 那版没复现，缺的就是兄弟分支信息），
   两条规则各自摘掉跑过，对应新用例都红。判分集 191/191、越界 0 未受影响。
3. **探针导出会带出用户选中的值**（我们自己查出来的，用户没提）：素描的隐私策略是
   "不复制 value、≤12 字的文本原样保留（取标签需要）"，但 AntD v3 把已选文案渲染在
   **控件节点之外**（`.ant-select-selection-selected-value`），清洗够不着 —— 真实导出里
   就出现过 `香港特别行政区`。而 `note` 当时写的是"本输出不含任何已填写内容"，这句话是错的。
   现在按类名白名单清空这些"已选文案"节点（白名单刻意收窄，`[class*="value"]` 会把要看标签的
   `span.field-value` 一起抹掉），`note` 改成能兑现的说法，并加了用例把 ≤12 字的选中值钉住。

**给用户的一句话结论**：不是 API 也不是模型 —— 那次"AI 没反应/被拦下"是我们自己的边界条件写得太粗，
真实资料一进页面就把闸门顶死了。现在它放行的是"页面本来就写着这个词"，拦住的是"只有你简历里才有"。

## 2026-10-01 · 同一张途普页面的第二层真相：33 个 radio/checkbox 是"皮肤控件"，插件一个都没看见

用户接着报："现在能填到选项，但实际填写的时候选项都是空的"，随后自己看了 DOM：
"实际上是 html 的 radio 和 checkbox 控件"。他的导出把这件事说死了 ——
`totals.radios = 5`、`totals.checkboxes = 28`，可 `fields`（41 条）里**一个 radio/checkbox 都没有**：

- AntD / Element 的真身是 `<input style="opacity: 0">`，看得见的方框是旁边那层装饰 span。
  `dom/scanner.js` 的 `visible()` 把 `opacity:0` 一律判为不可见 → 整组控件在扫描阶段就消失了。
  表现不是"填错"，而是"这一类问题插件根本不理"，用户只会觉得"其他都能填，就这几栏死"。
- 选项文案的取法也只写了 `nextElementSibling || parentElement`：皮肤结构里 input 没有元素兄弟，
  父级又是那层空的装饰 span，于是取回空串 —— 这就是"选项都是空的"。
  顺序很讲究：`<label><input>阅读</label>` 里文字是 label 的**文本节点**，
  而"父级的下一个兄弟"是隔壁选项（'跑步'）。先取兄弟就等于勾错框而且回读还是绿的。
  现在 `optionTextOf()` 统一为：自身兄弟 → 父级是选项壳就用父级文本 → 父级是装饰才看父级兄弟 → label → aria/title/value。
  `scanner`（列表）、`filler`（判命中）、`readBack`（回读）三处共用这一个函数，口径不再各写各的。
- `skinVisible()` 只在 radio/checkbox 上放行，并要求"皮肤本身可见"；从**父级**开始找皮肤
  （`el.closest('[class*="radio"]')` 会第一时间命中 input 自己那层 `opacity:0` 的 `.ant-radio-input`，
  判据恒假）。jsdom 里所有 rect 都是 0×0，所以尺寸判据带一个"排版不可用就不作为证据"的出口，
  真浏览器里 body 有尺寸，strictness 照旧。

顺手把用户直接要的东西做成界面功能：**「没填上的字段与选项对照」**（侧边栏新按钮）。
它导出每个没填上的控件 + `options: [{text 页面文案, value 提交码值}]` + 当前已选 + 没填的原因，
纯函数在 `core/option-map.js`，内容脚本没扫过时先 `dryRun` 只读算一遍（绝不写页面）。
之前每次问"这页为什么填不上"都要来回猜，这张表一次就能定位是词典没有这个词、
还是控件压根没扫到、还是码值形状对不上（'是'→`Y`）。

## 2026-10-02 · 埃森哲（途普）整页填乱：根因是**裸词 name 被多个板块当别名**

用户实测后的原话最值钱："**你把 name 识别成为 姓名，而不是 name**"、
"这个网站的 name 字段特别多，项目 name、实习 name、组织 name…全部识别为 name"、
"我不需要你按资料顺序填，我需要的是这个 name 在哪个板块的"、"school name 就是 school name"。

诊断（拿他自己的导出 + 同形状 synthetic profile 跑 `planFill` 复现）：

| 页面栏位 | 我们写进去的 | 为什么 |
| --- | --- | --- |
| `Name`（基本信息区） | 证书名称 `AWS Certified AI Practitioner` | `basics.name` 空 → **空槽根本不进候选** → 谁有值用谁 |
| `Address` | 邮箱 | 同上（`contact.address` 空着，`email address` 这条别名蹭上了） |
| `School Name` | 一度被派到 `certifications.0.name` | 裸词 `name` 同时挂在 证书名称/家庭成员·姓名 的别名表里（10 个槽位共用一个词） |
| `primary cell number`（区号下拉） | `basics.idNumber` | 'id number' ⊂ 'primary cell number' 覆盖率 0.53 就够过 0.52 的门槛，而 0.565 是黄字**照样写** |

四条修改，每条都有用例钉住：

1. **别名表里删掉裸词 `name`**（只留 `basics.name` 一处）；证书/家庭成员要命中必须说
   `certificate name` / `family member name`。这一条直接实现"school name 就是 school name"。
2. **空槽优先**：标签字面点名的槽位（分数 ≥0.9）在资料里是空的，就**留空并说明**，
   绝不拿别的栏位顶替 → 新缺口原因 `slot_empty`（"这一栏要的是「现居住地址」，你资料里还没填"）。
   只在"字面点名"时拦；第一版按分数差 0.05 就拦，把 `Certificate Name` 这种本来对的栏位也做没了（判分当场掉）。
3. **板块证据**：`sections: []` 不等于页面没有板块。新增"一个容器里排着几栏 → 它里面不含控件的
   那支短文本就是板块标题"的取法（`blockTitleOf`），标题文字与来源随字段一起导出（新列 `section`）。
   有了 hint，`Name` 在证书区就拿 `certificates.*.name`，在基本信息区才拿「姓名」。
4. **裸词 + 跨板块并列 + 零板块证据 → 不猜**：新缺口原因 `block_ambiguous`，note 里把候选板块念出来。
   判据收得很窄：只限"单个拉丁词"或"一两个汉字"的标签，且**同一个词在页面上出现两次以上**。
   第一版没做这两层收窄，Moka 的「公司名称」（一张表里出现两次、按最像的板块写才对）被整栏丢弃，
   判分 191→183 —— 过度拦截会让用户以为插件不认识这一页。

另外修的两个真问题：`entry.value` 缺失时以前会把字符串 `undefined` 写进页面（站点还当已填），
现在一律不写并报 `empty_value`；探针的祖先链从 7 层放宽到 14 层（上一轮"复刻失败"就是因为链子太短）。

判分 **191/191、越界 0**；测试 329 条全绿（这一轮 +7）。四条新判据各自摘掉跑过，对应用例都会红。

## 2026-10-02（续）· AI 的职责收回到"栏位 ↔ 槽位"这一件事上

用户这轮定的三句口径，全部落成了代码与用例：

> "AI 获取的就是栏位的信息要全面，整个页面的结构和栏位对应的名称和描述…这个对应做好了就不必发送候选值了，安全更好自然。"
> "敏感字段选槽位，不用一律黄字，因为我都要检查一遍。每换站点问一次。"
> "work permit 可以自动选，选不出就放那。"

**① 栏位档案采全。** 扫描新增 `description`（字段自己的说明文字：`label[for]`、`aria-describedby`、
紧邻的小字提示），问 AI 时随标签一起发出 `desc / section / name / id / 选项"文案=码值" / nearby / required`。
埃森哲那一页大量栏位标签就是裸的 `Name`，能区分"证书名称"和"本人姓名"的只有说明与板块 ——
以前这两样没发出去，模型只能猜。体积仍按四档降级（先削选项与描述，最后才少问栏位），
且**取值照旧一个字都不发**：新增用例同时钉"档案采全"与"采全之后自检依旧零泄漏"。

**② 档位口径改了。** `applyAiCandidates` 从"AI 选的一律 review"改成 `sensitive ? 'review' : 'auto'`，
`stats.review` 只数真待核对的那几条；`aiChosen` 标记与"AI 按语义建议用「…」"的说明照留，
界面里〔AI 选路〕角标仍在，撤销与审计认得这一笔。旧文案「AI 补齐 N 栏（全部黄字待你核对）」一并改掉。

**③ 站点级确认（第二道闸）。** `aiConsentOrigin` 只管"发去哪个 AI 地址"，一次勾完就在**任何**站点都放行，
而每一页的栏位名/选项文案/板块标题其实都在离开本机。现在按 `页面 origin → 当时确认过的端点 origin`
单独记一本账（`chrome.storage.local` 的 `aiSiteConsent` 顶层桶，**不进 settings**：settings 会被导出 JSON 带走，
而这本账记的是"你在哪些站点投过简历"）。页面 origin 由后台按 tabId 自己查，查不到（chrome://、about:blank）
判 `no_page_origin` 直接拒发，绝不"当作已确认"；改 Base URL 或清除 Key 时一起清账；界面反勾真的撤回。
踩的坑值得记：origin 形如 `https://job.example.test`，拿 `/^https?:$/` 去整串匹配会把每一站都判成"认不出"，
两道闸一起变成死闸 —— 集成测 8 条全红才发现（又是"只有真跑 SW 才看得见"那一类）。

**④ 区号型下拉只配 `contact.dialCode`。** 那一页把区号下拉和手机号输入框共用同一句标签
（primary cell number），于是区号格被派去拿证件号。半数以上选项形如 `+86 / +852` 时控件身份是确定的，
别的槽位派来的值一律不选，返回新原因 `dial_code_only`，与"这一栏得你亲自来"同一档（manual，不报红）。

**⑤ Work Permit 这类做成显式选项对照（`optionRules`）。** 页面问 Yes/No、资料存的是枚举
（`hkGlobal.workAuth` = 本地居民 / 需申请工作签证），字面永远对不上；让相似度或 AI 去够，
就是替用户在合规声明上表态。规则由适配器逐条写死：资料取值**只在单边**命中才算，
页面选项**必须恰好落一项**（两项都命中同样不选），拉丁别名整词命中（`no` 不落进 `Note`），
否定式选项走 `negationMismatch`（`是` 不落进`不是`），并且这一栏最后拿到的槽位必须等于规则写的槽位。
任何一条不满足 → 照旧 `needsChoice` 交人工，即"选不出就放那"。

| 现象 | 根因 | 改法 |
| --- | --- | --- |
| 五栏"读到"了区号那一列 | `openOptions` 在"点了没出现新弹层"时退回 `nowVisible` **全页扫描可见弹层**；同屏十几个 AntD 下拉，上一个还开着就被当成自己的 | 只认「这次点击新出现的」或「在自己壳子里的」弹层；一个都没有 → 新原因 `panel_ambiguous`，**一个选项都不点**。`collectOptions` 那条全页 `role=option` 退回同样收进本栏容器 |
| `School Name` / `Referrer Name` 全归"姓名" | 上一轮只删了别名表里的裸词 `name`，但 `scorePair` 是**成对**打分、看不见对手：末词命中 `label.endsWith('name')` 给到 0.695，压过真正被定语点名的 0.553 | 候选之间补一刀：纯拉丁多词标签 + 末词是通用词时，别名带定语的抬到 0.86，只靠通用词蹭的压到 0.7；**定语谁都不命中时完全不动**（不把 `Organization Name` 硬塞进某个槽） |

| `pinned_field_empty` 的 note 是空的（index 13 work permit） | 这条原因压根没进 `GAP_REASON_ZH`，表格直接印内部 token | 写出钉到了哪个槽位（`hkGlobal.workAuth`）并补中文说明 |

## 2026-10-03 · S4：标题是块边界；地名换算单独一层（顺带踩到一个两位码的坑）

用户口径（2026-10-02）："**先做完，先不管这个页面。但是 work permit 我就是 IANG**"。
IANG 那条落在枚举与选项方向锁里（已提交），这一节记 S4 的两件事。

**① 扫描器不跨标题边界。** 三处各错一次，都靠"摘掉实现必须变红"才钉住：

| 采集路径 | 错法 | 现在的判据 |
| --- | --- | --- |
| `prev-sibling` 往前遍历 | 走到上一节的标签，两块文字长得一样 | 遇到 `isBlockTitle` 就收手 |
| `:scope > label, [class\*="title"] …` | **标题自己**被当成"这一栏叫什么"（`class="section-title"` 命中属性选择器），新第一节整块共用一个标签 → 全糊到同一槽位 | 逐条看同层候选，标题跳过；节名只进 `sectionTitle`（那是板块证据） |
| `blockTitleOf` 找板块标题 | 不分位置，取容器里第一个不含控件的旁支 → 排在字段**后面**的下一节题目被认领，基本信息整节判给教育 | 只认 `el.compareDocumentPosition(k) & 2`（k 在本栏之前） |

`container-text` 那条同时改成**从本栏往前挨着看**，看到标题收手；原来从容器第一个孩子往后扫，
标题之前那段（上一节的标签）先进了候选。

**② 国别/省市的写法对照（`GEO_EQUIVALENTS` + `geoEnglishFor`）。** 之前 `equivalentsOf('中国')`
返回的还是"中国"，英文门户的 `Nationality / Country of Residence` 整片选不上；而英文页面缺英文值
默认**不写**（用户明确要求），于是港企最常空着的正是这一栏。现在：
下拉选项按中英两位码匹配；自由填写框在"整条取值就是一个地名"时由对照表换算（`中国 → China`），
换算过要在 `entry.note` 与 `plan.geoEnglish` 里留痕 —— 它不是资料原文，界面不能装作是。
`深圳市南山区` 这种拼过名的串换不出英文地名，照旧 `missing_english_value` 不写：半中半英比留空更糟。

**引入的坑（自己踩到并钉住）**：两位码进等价表后，`resolveOption` 的"包含即强匹配"会把
`上海→sh` 落进 **Washington**、`四川→sc` 落进 **Wisconsin**、`美国→us` 落进 **August**，
而地点下拉恰恰是这些词同时出现的地方。收紧成 `containable()`：拉丁串短于 4 个字符只许整条相等
（上一轮 exact 已经管了 `"CN"` 这种选项），中日韩两字本身是一个词（`硕士 → 硕士研究生` 是判分钉过的正例），
下限按文字种类分而不是一刀切。判分 191/191、越界 0，测试 411 条全绿。

## 2026-10-03（再续）· S6 独立审查回来 14 条：两条 Critical 都栽在"跨页面/跨栏"的接缝上

子 agent 审查（只读、自己写了探针跑）带回 2 Critical / 6 Important / 6 Minor。
两条 Critical 都不是"算法不聪明"，而是**边界穿错了**：

| 级别 | 现象 | 根因 | 修法 |
| --- | --- | --- | --- |
| Critical 1 | 在 A 招聘站改判并勾「记住」，若此时那个标签页已被用户翻到 B 站，规则会**存进 B 站的桶**，B 站一扫就命中并绿字写入 | 后台按 `tabId` 反查 origin 是对的，但侧边栏**没有标签页监听**，`tabId` 是上次扫描留下的；而指纹只用标签/name/id，跨站点常常撞得上（都叫 `Name`/`id="value"`） | 扫描回包带 `pageOrigin`；四条规则消息与扫描都带 `expectOrigin`，后台一比对不上就拒（`origin_changed` 中文回话），本轮确认丢弃但本站已记住的规则照旧；面板三个钮发消息前都重新取 `tabId` |
| Critical 2 | 映射表里对**月框**勾「这一栏不自动填」，计划照旧从年框那一笔把整个日期写进去，表里那一行还显示"本站规则：不填" | 年月组里非组长的成员在 `skip` 检查之前就 `return` 了；钉位会往组长传、**跳过不传** | 跳过也往组长传（整组不写），缺口说明写清是第几个框替他做的决定 |

Important 里最值得记的是**「来历报错」这一类**：摊平型槽位规则（`degreeSlotPins` 那一类）在改判之后仍先判，
于是用户明确改过的一栏被站点规则拿走，而映射表把这一步说成"本地词典匹配" ——
判错可以改，**理由编错会把信任一次性花掉**。现在改判同时压过 `pins` 与 `slotPins`，
`slotPins` 给的判定也标回 `adapter`。

其余按"不能装作"逐条收：AI 补的栏位必须跟着「按此映射填写」一起写（否则表上出现过又消失）；
落盘失败那一支也必须带 `confirmed`（嘴上说"仍按改判填写"、手上发的是不带改判的扫描）；
改判过的栏在换搜索词重画后仍要是 pending 样子（隐蔽的 armed 状态最危险）；
「我们不动这一栏」分 `yours` / `kept` 两种，站点已填的那种不能算成用户勾的；
撤销后重新只读扫一遍，而不是把映射表抹成"没扫到栏位"；
只读导出也带规则，免得面板与导出各说一套。

计划校验的四处假阳性（都是探针在 12 份判分页面里跑出来的）也一并收：
成对日期不再被报成"两栏抢同一个槽位"（同 `datePair` 算一栏）；
"页面几组"混合编号与无编号栏时不许数出虚假组数；
必填框**已经有值**时不再报"提交会被拦"；
页面没有"第几组"证据时不再报"资料多到没地方写"（这种页多半只要最高学历）——
`records_no_room` 以前在 12 份页面里的 8 份都触发，红字长挂就等于没有。
