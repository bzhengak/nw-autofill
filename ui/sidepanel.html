    AI 辅助导入（只处理本地解析器判不动的片段）
    

      本地解析按标题和小标题路由，简历里"直接写内容、不写'时间：'"这类写法会有剩下的一段段文字。
      这个功能把那些剩下的片段（不是整份简历）发给你自己配置的模型，让它判断该进哪个槽位。
      四条硬规则：① 只发判不动的片段，有总量上限；② 片段里出现身份证/护照/银行卡样式的内容，整段拒发；
      ③ 模型必须逐字摘录原文，返回值不是原文子串的一律丢弃（不许改写、翻译、统一日期格式）；
      ④ 结果先列出来给你勾选，勾了才写入，默认不覆盖已有值。
      每次点「问 AI」都会重新预览、重新确认，不记住上次的同意。

保险箱（加密备份到你选的本地文件）

  

    日常填写仍读浏览器里那份工作副本（明文，否则每次扫描都要你输口令）；这里做的是把它
    加密成一个文件交给你保存 —— 口令 → PBKDF2(600,000 轮) → AES-256-GCM，整份资料进密文。
    防的是"文件被别人拿走"（拷盘、误传网盘、电脑丢失）；防不住"你正开着侧边栏时别人看你的屏幕/内存"。
    口令没有找回机制：忘了就打不开，扩展里不存在任何后门。
  

  

    
  

  

    
    
    
    
  

  

    保存位置自己选，但注意：「文档」「桌面」常常在 OneDrive 的同步范围内，
    明文放过去等于把简历交给云；放本地文件也建议避开这些目录（或至少走这里的加密）。
    读文件优先用浏览器的文件选择器（Edge/Chrome 支持）；不支持时会自动退化成普通下载/上传。
  


  

    这些数据到底存在哪个文件里？
    

      全部存在浏览器自己的存储（chrome.storage.local）里：本扩展没有服务器，
      也没有申请 storage.sync 权限，所以它不会被同步到任何云端。Windows 上它落在浏览器的 LevelDB 目录：
    

    
Chrome: %LOCALAPPDATA%\Google\Chrome\User Data\<配置文件>\Local Extension Settings\<扩展ID>\
Edge:   %LOCALAPPDATA%\Microsoft\Edge\User Data\<配置文件>\Local Extension Settings\<扩展ID>\

    

      目录里的 *.ldb 与 *.log 就是数据本体。整个扩展只写三个键：
      profile（你填的简历，含中英两份值）、settings（Base URL、模型名、等待与长度上限、三个授权开关）、
      aiSecrets（只有勾了「记住 Key」才存在；没勾时 Key 只在 chrome.storage.session，关掉浏览器就没了）。
      扩展 ID 在 chrome://extensions 的卡片上能看到；解压加载的扩展 ID 由文件夹路径算出来，
      把仓库换到别的目录就会换成另一个 ID（旧目录里的数据不会跟过去，这也是"我资料怎么没了"的常见真因）。
    

    

      想看里面到底存了什么，别去读 .ldb（那是二进制）：在 chrome://extensions 点本扩展的
      「Service Worker」→ 打开 DevTools → Console 里执行
      chrome.storage.local.get(null).then(console.table)。
    

    

      说清楚代价：这个目录是明文，不加密。扩展拿不到系统钥匙串（要走 DPAPI 就得装本地程序，那违反"纯浏览器插件"）。
      所以任何能读到你这个 Windows 账户磁盘的进程或人都能取出简历内容（勾了「记住 Key」时连 Key 一起）。
      公用电脑请别勾「记住 Key」，用完按下面两步清干净。
    

    

      彻底清掉：① 在「简历数据」里把内容清空并保存（或点 AI 面板里的「清除」删 Key）；
      ② 在 chrome://extensions 移除本扩展，再删掉上面那个 <扩展ID> 目录。
      换机/重装前用「导出资料 JSON」带走 —— 那个文件只含 profile，不含端点与 Key。
    

  


  

    AI 兜底（只在本地词典答不上时问，且只问字段名）
    

      发出去的只有：页面上那一栏的文字、控件类型、页面选项文本，以及本扩展自带的槽位名。
      你的简历取值不会离开本机——发送前会再自检一次，命中就拒发。
      AI 只能"从已有槽位里挑一个"，不能生成内容，结果一律黄字、由你核对。
    

    

      
      
    

    

      
      
    

    

      
      
    

    
    

      为什么默认开：非流式响应在整段答案生成完成之前一个字节都不发，于是"对端在慢慢想"和
      "路径根本不通"在界面上完全同形（实测过：非流式 15 秒零字节，流式立刻开始回话）。
      服务商不认 stream 参数时会自动退回普通收法再试一次，不需要你手动切。
    

    

      回答长度上限 = 请求里的 max_tokens。reasoning 模型把思考链也算进这个数，      几十个缺口的 JSON 回答本来就要几千 token：给小了会出现"正文是空的"或"答案被砍断"，
      看起来像模型没建议，其实是没留够写字的地方。默认 4000（可填 500–16000），
      用 R1 / QwQ / Qwen3 思考模式时建议 6000 起。
    

    

      等待上限：模型答得慢就多等，超时是最难归因的失败（看起来像"没反应"，其实是还没答完）。
      默认 180 秒，可填 15–900；reasoning 模型回答几十个缺口时建议 300 秒起。
      等待期间状态栏会每秒报"已等待多少秒"，不是在黑箱里干等。
    

    

      
      
      
    

    
    

      勾上后 Key 会写进浏览器自己的 profile 目录（chrome.storage.local 的独立 aiSecrets 桶）。
      扩展拿不到系统钥匙串，所以它是明文落盘：任何能读到你这个 Windows 账户磁盘的人都能取出。
      它不在 settings 里，因此不会随「下载空白模板 / 编辑导入 JSON / 导出本页结构」离开本机；
      用「清除」两个位置一起删。公用电脑或别人能碰你电脑的情况，建议别勾。
